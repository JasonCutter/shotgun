회의 상태: 완료
결정일: 2026-07-12
### 확정 결정
1. 초기 입력 채널은 파일 업로드(FILE_UPLOAD), 직접 텍스트 입력(TEXT_ENTRY), URL 제출(URL_SUBMISSION)의 세 가지로 한다.
2. 대화는 독립 입력 채널이 아니라 파일·텍스트·URL을 통해 들어오는 의견·참고 자료 유형(MaterialKind = CONVERSATION)으로 정의한다.
3. 초기 지원 자료 범위에는 일반 문서, Markdown·일반 텍스트, PDF, 스프레드시트·표(Excel·CSV 등), 프레젠테이션(PowerPoint 등), 이미지, 웹페이지, 대화·회의록·인터뷰 기록, 소스 코드·설정 파일의 텍스트 자료를 포함한다.
4. YouTube 등 영상 페이지 URL은 접근 가능한 제목·설명·자막·스크립트를 텍스트로 확보하여 요약·정리하는 범위에서 지원한다. 영상 프레임, 음성, 장면을 직접 분석하는 기능은 초기 범위에 포함하지 않는다.
5. 모든 입력 채널은 공통 IntakeSubmission 계약으로 정규화해 Step 2로 전달한다. 상세 필드 스키마는 후속 Section에서 확정한다.
### 결정 근거
입력 방법인 Channel과 자료의 성격인 MaterialKind를 분리하면 같은 자료를 여러 경로로 접수할 수 있고, 향후 Connector나 Watcher를 추가해도 핵심 처리 계약을 유지할 수 있다. 파일·텍스트·URL의 세 채널은 초기 Source Intake를 가장 단순하게 구성하면서 주요 사용 사례를 포괄한다.
### 연기·제외한 범위
로컬 폴더 전체 가져오기, 폴더 자동 감시, Google Drive·Notion·Slack·Gmail 등의 직접 Connector, GitHub 저장소 전체 수집과 웹사이트 전체 크롤링은 초기 범위에서 연기한다. 압축 파일 묶음과 실행 파일·프로그램 바이너리는 지원 범위에서 제외한다. 오디오·영상 파일 직접 분석, 자막이 없는 영상의 자동 음성 전사, 영상 프레임·음성·장면 분석은 초기뿐 아니라 장기 확장 범위에서도 제외한다. 영상 URL에서 텍스트를 확보할 수 없는 경우에는 ‘텍스트 확보 불가’ 상태로 표시하고 사용자에게 스크립트 제공을 요청한다.
### 영향 범위와 후속 검토
파일 입력의 확장자·크기·구형 Office 형식·암호화 문서·업로드 경험은 Section 1.2, 직접 텍스트 입력은 Section 1.3, URL 제공자·YouTube·접근 실패 처리는 Section 1.4, 대화 자료의 세부 유형은 Section 1.5에서 검토한다. 실제 URL 안전성, 리디렉션, 형식·인코딩·중복 검사는 Step 2에서 다루고, 자막·스크립트의 실제 추출 실패는 Step 4에서 다루며, 원본 보존과 영구 레코드는 Step 3에서 다룬다.
### 미결사항
정확한 파일 확장자 목록, 파일 크기 제한과 초과 처리, 구형 Office 형식 지원 여부는 Section 1.2에서 결정한다. YouTube 자막 확보 우선순위와 URL 단계의 실패 상태는 Section 1.4에서 결정하고, 기술 검증·추출 실패 상태는 Step 2와 Step 4에서 구체화한다.
