회의 상태: 완료
결정일: 2026-07-12
### 확정 결정
1. 직접 텍스트 입력은 일반 텍스트 전용 편집기로 제공한다. 주된 사용 방식은 웹페이지나 다른 문서에서 기억할 내용을 복사해 붙여넣고 필요한 설명을 짧게 덧붙이는 것이다.
2. Markdown 편집 기능, 리치 텍스트 편집 기능, 서식 도구 모음, 미리보기 기능은 제공하지 않는다. 사용자는 별도 문법을 알 필요 없이 글자만 입력하거나 붙여넣을 수 있어야 한다.
3. 웹페이지나 문서에서 붙여넣을 때 글꼴·색상·글자 크기·페이지 배치 등 외형 서식은 제거한다. 텍스트의 순서, 문단과 줄바꿈, URL 문자열은 가능한 범위에서 유지하며 Markdown으로 자동 변환하지 않는다.
4. 입력창에 포함된 URL은 원문의 일부로만 보존하며 자동 방문하거나 외부 내용을 수집하지 않는다. 웹페이지 자체를 자료로 수집할 때는 Section 1.4 URL 입력을 사용한다.
5. 붙여넣은 이미지는 직접 텍스트 자료에 포함하지 않고 제외 사실을 사용자에게 알린다. 이미지는 Section 1.2 파일 입력을 사용한다. 표는 가능한 범위에서 행·열 관계를 일반 텍스트로 유지하고, 코드는 실행하지 않고 텍스트로만 취급한다.
6. 제출 버튼을 누른 시점의 텍스트를 원본 입력으로 고정한다. 후속 정리·분석·변환 결과는 파생 결과로 생성하며 제출 원문을 조용히 덮어쓰지 않는다.
7. 출처, 발언자·작성자, 사용자 메모와 같은 구조화 정보는 편집기 기능에 포함하지 않고 Section 1.7 입력 시 사용자 지정 정보에서 별도 필드와 선택 여부를 설계한다.
### 결정 근거
사용자는 직접 장문을 작성하거나 Markdown 문법으로 문서를 만드는 것보다 외부 자료에서 필요한 내용을 복사해 저장하고 출처·발언자 정보를 덧붙이는 방식으로 사용할 가능성이 높다. 따라서 작성 도구의 기능을 늘리기보다 붙여넣기 결과가 예측 가능하고 원문이 안정적으로 보존되는 단순 입력창이 적합하다.
### 제외한 대안
Markdown 편집기, 리치 텍스트 편집기, 글꼴·색상·표·이미지 편집 도구, 붙여넣은 URL의 자동 수집, 붙여넣은 이미지의 자동 파일 등록은 채택하지 않는다.
### 영향 범위와 후속 검토
출처·발언자·작성자·사용자 메모의 구조화 입력은 Section 1.7에서 결정한다. URL 실제 수집은 Section 1.4, 여러 텍스트 자료의 동시 제출은 Section 1.6, 입력 길이·임시 저장·진행 상태·제출 실패 후 복구와 같은 공통 화면 동작은 Section 1.9에서 결정한다. 원본 저장과 제출 후 정정 이력은 Step 3에서 구체화한다.
### 미결사항
Section 1.3의 편집기 성격과 붙여넣기 정책에는 정책 수준의 미결사항이 없다. 입력 길이는 Section 1.9에서 항목당 100,000자로 확정했고, 제출 전 자동 초안 저장은 제공하지 않으며 화면 이탈 경고만 제공한다.
