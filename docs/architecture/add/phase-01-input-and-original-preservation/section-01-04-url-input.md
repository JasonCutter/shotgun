회의 상태: 완료
결정일: 2026-07-13
### 확정 결정
1. URL 입력은 로그인 없이 공개적으로 접근 가능한 [http://와](http://와) https:// 주소만 지원한다. [https://app.notion.com](https://app.notion.com), ftp://, mailto:, tel:, data:와 로컬 경로·사설 네트워크 주소는 지원하지 않는다.
2. 하나의 URL 제출은 하나의 Source Item 후보를 만든다. 제출한 페이지의 링크, 관련 글, 첨부 링크, 사이트·저장소·채널·재생목록 전체를 자동으로 따라가거나 수집하지 않는다.
3. 공개 웹페이지, 공개 직접 파일 URL, 영상 페이지 URL을 구분한다. 직접 파일 URL이 Section 1.2의 지원 형식과 한도를 충족하면 파일 입력 처리 경로로 전달하고, 사용자가 제출한 URL은 해당 파일의 Provenance로 보존한다.
4. 최초 제출 URL과 안전한 리디렉션을 거친 최종 URL을 모두 보존한다. 정상 리디렉션과 단축 URL은 허용하되 리디렉션 횟수 제한, 사설 주소 이동, 반복·위험 리디렉션 판정은 Step 2에서 처리한다.
5. URL 자료는 제출 시점에 한 번 가져온 스냅샷으로 취급하고 접근 시각을 기록한다. 초기 버전은 페이지 변경 감시, 주기적 재수집, 자동 갱신을 수행하지 않는다.
6. 로그인 계정, 비밀번호, 브라우저 쿠키·세션, 유료 구독, CAPTCHA 또는 접근 통제를 우회하지 않는다. 접근에 권한이 필요한 경우 ‘접근 권한 필요’ 상태를 표시하고 파일 업로드, 직접 텍스트 입력 또는 공개 링크 제출을 안내한다.
7. 일반 웹페이지에서는 제출 URL, 최종 URL, 도메인·제공자, 감지된 자료 종류, 페이지 제목, 접근 시각, 공개 접근 가능 여부와 본문 텍스트 확보 가능 여부를 기록한다. 실제 HTML 정리와 본문·작성자·게시일·표 추출은 Step 4\~5에서 수행한다.
8. YouTube 등 영상 페이지에서는 공개적으로 확보 가능한 제목·설명·채널·게시일과 자막·스크립트만 사용한다. 자막 우선순위는 업로더 제공 공식 자막·스크립트, 플랫폼 자동 생성 자막, 공개 메타데이터 순으로 한다.
9. 자막이나 스크립트를 확보하지 못한 영상은 제목·설명만으로 영상 전체를 요약하거나 Claim을 추출하지 않는다. ‘자막 없음’ 또는 ‘영상 본문 텍스트 확보 불가’ 상태를 표시하고 사용자가 스크립트를 직접 제공하도록 안내한다.
10. 영상 프레임, 음성, 장면 분석과 자막 없는 영상의 자동 음성 전사는 초기 범위뿐 아니라 장기 확장 범위에서도 제외한다.
11. 사용자에게 표시할 최소 상태는 접수 가능, 접근 권한 필요, 지원 불가, 본문 없음, 자막 없음, 일시적 접근 실패로 구분한다. 실제 확보 범위와 부족한 범위를 정상 처리처럼 숨기지 않는다.
### 결정 근거
URL 제출은 사용자가 특정 공개 자료를 명시적으로 수집하라는 행위다. 한 주소의 직접 콘텐츠만 단일 스냅샷으로 가져오고 제출 URL과 최종 URL, 접근 시각과 확보 범위를 함께 남기면 Provenance를 유지하면서 무제한 크롤링과 권한 우회 위험을 피할 수 있다. 영상은 텍스트 근거가 확보된 경우에만 지식 처리 대상으로 삼는다.
### 제외한 대안
로그인 세션·쿠키를 이용한 비공개 페이지 접근, 유료벽·CAPTCHA 우회, 링크 추적 크롤링, 사이트·저장소·채널·재생목록 전체 수집, 페이지 자동 감시·갱신, 영상·음성·장면·프레임 직접 분석과 자동 음성 전사는 채택하지 않는다.
### 영향 범위와 후속 검토
URL 안전성, SSRF 방지, 사설 IP·[localhost](http://localhost) 차단, 리디렉션 제한은 Step 2에서 결정한다. URL 원본과 수집 스냅샷의 영구 보존은 Step 3, HTML·자막 추출과 정규화는 Step 4, 페이지 구조·작성자·게시일·표와 자막 언어 분석은 Step 5, 번역 자막 연결은 Step 7에서 구체화한다. 여러 URL 제출은 Section 1.6, 사용자 지정 정보는 Section 1.7에서 결정했다. 입력 단계 처리 지시는 Section 1.8에서 제공하지 않기로 확정했으며, 진행률·취소·재시도 UI는 Section 1.9에서 결정한다.
### 미결사항
Section 1.4의 정책 수준 미결사항은 없다. 제공자별 추출 구현, 상태 코드 명칭, 재시도 횟수와 시간 제한은 후속 기술 설계에서 확정한다.
