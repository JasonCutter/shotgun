회의 상태: 완료
결정일: 2026-07-13
### 확정 결정
1. 한 번의 제출에서 복수 파일, 복수 URL과 하나 이상의 직접 텍스트 항목을 자유롭게 혼합할 수 있다.
2. 사용자가 제출 버튼을 한 번 누르면 하나의 IntakeSubmission이 생성된다. 묶음 안의 파일·텍스트·URL 각각은 독립된 Source Item 후보이며, 같은 묶음에 포함됐다는 사실만으로 자료 사이의 지식 관계를 만들지 않는다.
3. 한 번의 제출은 파일·텍스트·URL을 합쳐 최대 20개 항목으로 제한한다. 파일은 기존 정책대로 파일당 최대 50MB, 파일 총용량 최대 200MB이며 텍스트와 URL은 파일 용량 합계에 포함하지 않는다.
4. 하나의 직접 텍스트 입력 상자는 하나의 Source Item 후보다. 사용자는 텍스트 입력 상자를 여러 개 추가할 수 있다.
5. 사용자가 배치한 순서를 제출 순서로 보존하고 결과 목록도 기본적으로 같은 순서를 유지한다. 제출 전에는 항목 순서를 변경할 수 있다. 이 순서는 중요도·인과관계·자료 관계를 의미하지 않는다.
6. 제출 전에는 모든 항목을 개별 제거할 수 있다. 빈 텍스트, 잘못된 URL, 명백한 형식 오류가 있는 항목은 사용자에게 사유를 알리고 제출 순간 폐기한다. 해당 항목은 Source Item 후보를 만들지 않으며 제출 결과에는 ‘제외됨’ 상태와 사유만 남긴다. 정상 항목의 제출은 계속한다.
7. 항목별 최소 상태는 대기, 업로드·접수 중, 처리 중, 완료, 제외됨, 실패, 취소됨으로 한다. 제출 묶음 상태는 진행 중, 완료, 부분 완료, 실패, 취소됨으로 구분하며 완료 항목과 제외·실패·취소 항목이 함께 있으면 부분 완료로 표시한다.
8. 사용자가 제출 묶음 전체를 취소하면 대기·진행 중 항목을 중단하고, 이미 완료된 항목을 포함해 해당 IntakeSubmission에서 새로 접수한 원본과 파생 결과를 모두 삭제한다. 이전 제출에서 저장된 별도 Source Item이나 Canonical 지식은 삭제하지 않는다.
9. 실패한 항목은 해당 항목만 개별 재시도할 수 있다. 완료·제외·취소 항목을 자동으로 다시 처리하지 않으며 재시도 시도 기록의 상세 모델은 후속 기술 설계에서 확정한다.
10. 입력 화면에서 중복으로 보이는 항목은 경고할 수 있지만 자동 병합하거나 제거하지 않는다. 실제 정확 중복 판정은 Step 2에서 수행한다.
11. 대화 자료를 다른 자료와 함께 제출할 수 있지만 Section 1.5의 의견·참고 전용 정책은 그대로 유지한다.
### 결정 근거
혼합 제출과 독립 항목 처리는 사용자가 관련 자료를 한 번에 넣는 편의성을 제공하면서 한 항목의 오류가 나머지 자료를 막는 문제를 피한다. 공통 20개 제한과 제출 순서 보존은 설명과 결과 확인을 단순하게 한다. 전체 취소 시 이번 제출의 원본과 결과를 모두 폐기하면 사용자가 취소한 자료가 일부 남는 불명확한 상태를 만들지 않는다.
### 제외한 대안
파일·URL·텍스트를 별도 제출하도록 강제하는 방식, 파일 20개와 URL·텍스트 한도를 별도로 계산하는 방식, 문제 항목 하나 때문에 전체 제출을 막는 방식, 완료된 항목을 전체 취소 후에도 유지하는 방식, 입력 단계 자동 중복 병합은 채택하지 않는다.
### 영향 범위와 후속 검토
프로젝트·자료 성격·작성자·화자·날짜·태그·접근 범위·민감도와 자료 간 사용자 지정 관계는 Section 1.7에서 결정한다. 입력 단계의 공통·자료별 처리 지시는 Section 1.8에서 제공하지 않기로 확정했으며, 입력 화면 배치·진행률·취소 확인 UI와 텍스트 길이 제한은 Section 1.9에서 확정했다. 실제 형식·안전성·정확 중복 검사는 Step 2, Source Item과 IntakeSubmission의 영구 저장·삭제·Audit 계약은 Step 3에서 구체화한다.
### 미결사항
정책 수준의 미결사항은 없다. 재시도 Attempt 식별자, 전체 취소 삭제 트랜잭션과 보존할 최소 Audit 정보, 상태 코드의 내부 명칭은 후속 기술 설계에서 확정한다.
