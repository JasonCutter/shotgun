회의 상태: 완료
결정일: 2026-07-13
### 확정 결정
1. 자료 제출에 필요한 필수 입력은 파일·직접 텍스트·URL 원문뿐이다. 입력 시 사용자가 추가로 제공할 수 있는 정보는 각 Source Item에 연결되는 선택적 사용자 메모 하나로 제한한다.
2. 표시 제목은 시스템이 자동 생성한다. 파일은 파일명, URL은 페이지 제목 또는 URL, 직접 텍스트는 내용 기반 요약 제목을 기본값으로 사용한다. 제목은 화면 구분을 위한 표시값이며 지식 구조나 원문을 변경하지 않는다. 사용자는 지식화 이후 제목을 수정할 수 있다.
3. 입력 단계에서는 프로젝트를 지정하지 않는다. 지식화 이후 사용자가 필요한 자료·지식을 찾아 프로젝트로 묶을 수 있으며 하나의 자료·지식은 여러 프로젝트에 포함될 수 있다. 프로젝트 연결은 다대다 관계를 전제로 한다.
4. 대화 자료는 Section 1.5에 따라 의견·참고 자료로 유지한다. 그 밖의 Source Item에는 사용자가 자료 성격을 지정하지 않으며 기본 지식화 파이프라인의 입력 대상으로 취급한다. 다만 입력 순간에는 Canonical 지식이나 Fact로 간주하지 않는다.
5. 사용자가 출처명·출처 URL을 입력하는 전용 필드는 제공하지 않는다. 파일명·원본 파일, 제출 URL·최종 URL·접근 시각, 직접 텍스트 원문 등 Provenance는 시스템이 자동 보존한다. 직접 텍스트의 출처를 확인할 수 없으면 출처 미확인 상태를 허용한다. 본문이나 메모에 출처 단서가 있으면 후속 단계에서 추출 후보로 사용할 수 있다.
6. 작성자·발언자 입력 필드와 연락처 검색·선택 기능은 제공하지 않는다. 시스템이 원문에서 작성자·발언자·Entity 후보를 추출하되, 모호한 동일인 병합과 관계는 승인 전 후보로 유지하고 Canonical Entity를 조용히 확정하지 않는다.
7. 사용자는 원문 작성일·발행일을 입력하지 않는다. 시스템이 원문 또는 플랫폼 메타데이터에서 날짜를 추출할 수 있으면 source_date와 근거를 기록하고, 추출할 수 없으면 source_date는 미상으로 둔다. ingested_at은 별도로 항상 기록하며 입력 시각을 원문 날짜로 대체하지 않는다.
8. 태그는 지식화 과정에서 시스템이 자동 생성한다. 사용자는 지식화 이후 태그를 추가하거나 삭제할 수 있다. 자동 태그 원본과 사용자 수정 이력은 구분해 보존한다.
9. 사용자 메모는 Source Item에 한 번만 저장하고 파생 지식마다 복제하지 않는다. 해당 Source Item에서 파생된 지식이 검색·조회될 때 연결된 사용자 메모를 함께 표시한다.
10. Shotgun은 개인 전용 시스템으로 운영하며 입력 시 접근 범위나 팀·조직 권한을 지정하지 않는다. 외부 공유는 권한 부여가 아니라 사용자가 선택한 지식을 PDF 또는 HTML 파일로 내보내는 방식이며 Phase 6의 결과 제공 설계에서 다룬다.
11. 사용자가 지정하는 민감도 필드는 제공하지 않는다. 자격 증명, API 키, 개인 식별정보, 금융·의료정보 등은 시스템 안전 플래그로 자동 감지하며 저장·처리·내보내기 전 경고와 보호 정책에 사용한다.
12. 시스템 생성값과 사용자의 후속 수정값이 충돌하면 둘 다 보존한다. 표시 제목·태그처럼 사용자가 수정할 수 있는 값은 화면에서 사용자 수정값을 우선 표시한다. 작성자·날짜·Entity처럼 사실성에 영향을 주는 값은 각 값의 근거와 충돌 상태를 함께 유지하며 조용히 덮어쓰지 않는다.
13. 사용자는 자료 간 관계나 연결을 직접 지정하지 않는다. 시스템이 관계 후보를 탐색·생성하되 AI 결과는 승인 전 후보이며 Canonical 관계로 자동 확정하지 않는다.
14. 제출 묶음 공통 메타데이터와 개별 덮어쓰기 기능은 제공하지 않는다. 사용자 메모는 자료별로만 연결한다.
### 결정 근거
Shotgun의 목적은 사용자가 입력 전에 자료를 분류하고 메타데이터를 관리하게 하는 것이 아니라, 원문을 빠르게 접수한 뒤 시스템이 Provenance·구조·태그·Entity·관계를 생성하고 사용자가 필요한 지식을 찾게 하는 것이다. 제목은 표시 편의를 위한 보조값이고, 출처는 사용자 입력 필드가 아니라 검증·충돌 분석·원문 재확인을 위한 시스템 핵심 기록이다. 사용자 메모만 원자료에 연결하면 입력 부담과 중복을 줄이면서 사용자가 남긴 맥락을 검색 결과에 유지할 수 있다.
### 제외한 대안
입력 시 프로젝트 필수·선택 지정, Source Item당 단일 주 프로젝트, 자료 성격 분류, 출처·작성자·날짜·태그·접근 범위·민감도 직접 입력, 연락처 검색, 자료 간 관계 직접 설정, 제출 묶음 공통 메타데이터, 파생 지식마다 사용자 메모 복제는 채택하지 않는다. AI가 모호한 Entity·관계를 승인 없이 Canonical로 확정하는 방식도 채택하지 않는다.
### 영향 범위와 후속 검토
입력 화면에는 자료 원문과 자료별 선택 메모만 노출한다. 표시 제목 생성과 수정 UI, 자동 태그와 프로젝트 다대다 연결, 사용자 수정 이력은 후속 데이터 모델과 활용 화면에서 구체화한다. Provenance 영구 저장은 Step 3, 작성자·날짜·Entity·관계 추출은 Step 5와 Phase 3, 안전 플래그와 내보내기 전 경고는 Step 2 및 공통 보안 설계, PDF·HTML 내보내기는 Phase 6 Step 20에서 다룬다. Section 1.3에서 출처·발언자·사용자 메모를 모두 구조화 입력으로 검토하기로 한 이전 기록은 이번 결정으로 변경되며 사용자 메모만 입력 항목으로 남는다.
### 미결사항
Section 1.7의 정책 수준 미결사항은 없다. 자동 제목 생성 규칙, 태그 편집 이력, 프로젝트 연결 테이블, 안전 플래그 종류와 충돌 표시 UI의 상세 구현은 후속 설계에서 확정한다.
