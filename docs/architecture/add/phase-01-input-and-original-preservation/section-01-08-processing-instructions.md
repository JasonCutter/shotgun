회의 상태: 완료
결정일: 2026-07-14
### 확정 결정
1. 입력 단계에는 자료별 또는 제출 묶음별 처리 지시 기능을 제공하지 않는다.
2. 사용자는 파일·직접 텍스트·URL 원문과 선택적 사용자 메모만 제출하며, 일반 Source Item은 시스템의 표준 지식화 파이프라인으로 자동 처리한다.
3. 대화 Source Item은 Section 1.5 정책에 따라 의견·참고 자료로 보존하고 기본 지식화 파이프라인에 자동 투입하지 않는다.
4. 요약·번역·비교·재분석·특정 구조 추출 등의 사용자 요청은 Source Item이 저장된 이후의 활용 또는 재처리 단계에서 수행한다.
5. 입력 화면과 IntakeSubmission 계약에는 자유문 처리 지시, 미리 정의된 처리 옵션, 제출 묶음 공통 지시와 자료별 덮어쓰기 필드를 두지 않는다.
6. 입력 이후의 재처리는 원문을 변경하지 않는 별도 실행과 파생 결과로 기록하며, AI 결과와 사용자 요청은 Canonical 승인 경계를 우회하지 않는다.
7. 미래 자료에 반복 적용되는 영구 규칙은 입력 단계의 일회성 지시가 아니라 별도 User Directive와 승인 절차에서 관리한다.
### 결정 근거
Shotgun의 입력 단계는 사용자가 매번 프롬프트를 작성하는 작업 화면이 아니라 원문을 빠르게 접수하고 Provenance를 보존하는 경계다. 입력 시 처리 지시를 제거하면 화면과 계약이 단순해지고 모든 일반 자료에 동일한 표준 파이프라인을 적용할 수 있으며, 자료 분류·추출·안전 검사·지식 후보 생성의 책임을 시스템에 유지할 수 있다. 저장 이후의 요청은 고정된 Source Item을 대상으로 실행하므로 원문과 입력 근거를 변경하지 않고 다양한 활용 결과를 만들 수 있다.
### 제외한 대안
입력 시 선택적 자유문 처리 지시, 미리 정의된 요약·번역·추출 옵션, 제출 묶음 공통 지시와 자료별 덮어쓰기, 사용자가 제출 전에 원문 보존·요약·번역·지식화 방식을 선택하는 구조는 채택하지 않는다. 입력 지시를 이용해 대화 자료 정책, 안전 규칙 또는 Canonical 승인 절차를 우회하는 방식도 허용하지 않는다.
### 영향 범위와 후속 검토
입력 화면에는 자료 원문과 Section 1.7에서 확정한 자료별 선택 메모만 제공한다. 입력 화면 배치·완료 조건·진행률·취소·재시도는 Section 1.9에서 결정한다. 표준 지식화 파이프라인의 실행은 Phase 2\~3, 저장 이후 요약·번역·비교·재분석과 결과 제공은 Phase 6 Step 18\~20, 영구 User Directive의 생성과 승인은 Phase 4 Step 14에서 구체화한다. 재처리 실행의 Job·Attempt·Audit와 원본·파생 결과 보존은 Step 3과 공통 아키텍처 설계에서 다룬다.
### 미결사항
Section 1.8의 정책 수준 미결사항은 없다. 저장 이후 활용·재처리 요청의 구체적 UI, 작업 상태, 재시도와 Audit 데이터 모델은 후속 설계에서 확정한다.
