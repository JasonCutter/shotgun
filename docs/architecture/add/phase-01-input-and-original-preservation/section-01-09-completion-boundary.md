회의 상태: 완료
결정일: 2026-07-14
### 확정 결정
1. 파일·URL·직접 텍스트는 별도 페이지나 탭으로 나누지 않고 하나의 통합 자료 제출 화면에서 추가한다. 상단에는 파일 추가, URL 추가, 텍스트 추가 동작을 제공한다.
2. 추가된 모든 자료는 하나의 순서 목록에 카드 형태로 표시한다. 각 카드에는 자료 종류, 파일명·URL·텍스트 임시 표시명, 현재 검증 상태, 선택적 사용자 메모, 순서 변경과 제출 전 제거 기능만 제공한다. 프로젝트·태그·출처·작성자·날짜·민감도와 처리 옵션은 표시하지 않는다.
3. 사용자가 추가한 순서를 기본 제출 순서로 보존하고 제출 전에는 순서를 변경할 수 있다. 이 순서는 중요도·인과관계·자료 관계를 의미하지 않는다. 파일 변경은 기존 항목 제거 후 다시 추가하고, URL과 직접 텍스트는 제출 전에 수정할 수 있다.
4. 제출 전 검증은 사용자가 즉시 고칠 수 있는 명백한 오류만 담당한다. 빈 텍스트, 잘못된 URL·프로토콜, 지원하지 않는 파일 확장자와 파일당 50MB 초과는 항목 오류로 표시하고 제출 대상에서 제외한다. 정상 항목은 계속 제출한다. 총 20개 항목 또는 파일 총용량 200MB를 초과하면 사용자가 항목을 줄이기 전까지 제출 묶음 전체를 제출할 수 없다. 유효한 항목이 하나도 없으면 제출 버튼을 비활성화한다.
5. 직접 텍스트는 Source Item 후보 한 건당 최대 100,000자로 제한한다. 이를 초과하는 자료는 .txt, .md 또는 .docx 등 지원 파일 형식으로 제출한다.
6. 제출 전 직접 텍스트·URL·사용자 메모를 브라우저 로컬 저장소나 서버에 자동 초안 저장하지 않는다. 입력 내용은 현재 화면 세션에서만 유지하며 미제출 내용이 있을 때 새로고침·화면 이탈·창 닫기를 시도하면 손실 경고를 표시한다. 새로고침이나 재접속 후 선택한 파일과 미제출 내용을 자동 복원하지 않는다.
7. 사용자 상태에는 제출됨, 접수 완료, 자동 처리 완료를 구분한다. 제출됨은 서버가 요청과 IntakeSubmission 식별자를 수락한 상태, 접수 완료는 원문·URL 스냅샷과 Provenance가 안전하게 저장되고 Source Item 후보 식별자가 생성된 상태, 자동 처리 완료는 후속 검증·추출·분석·후보 생성이 정책 범위에서 종료된 상태다.
8. 성공한 항목의 Step 1 입력 완료 기준은 접수 완료다. 제외됨·실패·취소됨은 성공적인 입력 완료가 아니라 해당 항목의 종결된 접수 결과다. 제출 묶음은 모든 항목이 접수 완료·제외됨·실패·취소됨 중 하나의 안정 상태에 도달하면 Step 1 처리를 종료하고 완료·부분 완료·실패·취소됨으로 결과를 표시한다.
9. 사용자는 제출됨 이후 입력 화면을 떠날 수 있으며 서버의 접수와 후속 자동 처리는 계속된다. 재접속 시 IntakeSubmission 식별자를 기준으로 현재 상태와 항목별 결과를 복원한다.
10. 항목 상태는 대기, 업로드·접수 중, 접수 완료, 자동 처리 중, 완료, 제외됨, 실패, 취소됨으로 구분한다. 제출 묶음 상태는 제출 중, 접수 완료, 처리 중, 완료, 부분 완료, 실패, 취소됨으로 구분한다. 숫자 진행률은 파일 업로드처럼 측정 가능한 작업에만 사용하고 추출·분석에는 단계형 상태를 사용한다.
11. 전체 취소는 제출·접수 또는 자동 처리가 진행 중일 때만 제공한다. 취소 확인 화면은 이번 IntakeSubmission에서 이미 접수된 원본과 파생 결과도 모두 삭제된다는 점을 명시한다. 확인 후에는 취소 처리 중 상태를 거쳐 Section 1.6과 ADR-002의 전량 폐기 정책을 적용한다. 완료·부분 완료·실패 등 종결 상태 이후의 제거는 취소가 아니라 Step 3에서 설계할 별도 삭제 기능으로 처리한다.
12. 실패한 항목만 개별 재시도할 수 있다. 동일한 원문에 대한 재시도는 같은 Source Item 후보의 새로운 Attempt로 기록한다. 파일·URL·텍스트 원문을 수정하면 재시도가 아니라 새 항목 또는 새 IntakeSubmission으로 처리한다.
13. 입력 화면은 자료 추가·제출 전 편집, 선택 메모, 명백한 개수·용량·형식 오류 확인, 제출 요청, 상태 표시, 진행 중 전체 취소와 실패 항목 재시도 UI, 화면 이탈 경고를 담당한다. Step 2는 실제 형식·인코딩·안전성·정확 중복을 검증하고, Step 3은 원본 자산·IntakeSubmission·Source Item·Attempt·Audit·삭제 트랜잭션과 원본 불변성을 담당한다. Phase 2 이후는 콘텐츠 추출·구조 분석·지식 후보 생성·승인과 활용을 담당한다.
14. 입력 화면에서는 프로젝트 선택, 자료 성격 분류, 제목·출처·작성자·날짜·태그·관계·민감도 입력, 처리 지시, 자동 추출 결과 승인, Canonical 지식 편집과 저장 이후 요약·번역·비교를 수행하지 않는다.
### 결정 근거
통합된 짧은 입력 흐름과 부분 성공 정책은 자료 수집 부담을 줄이면서 한 항목의 오류가 정상 자료를 막지 않게 한다. 입력 완료를 원문과 Provenance의 안전한 접수로 한정하면 사용자가 긴 자동 처리 동안 화면에 머물 필요가 없고, 후속 단계의 실패가 원본 접수 성공과 혼동되지 않는다. 제출 전 자동 초안 저장을 제외하면 API 키·개인정보·의료·금융정보가 사용자의 명시적 제출 전에 브라우저 저장소에 남는 위험을 피할 수 있다.
### 제외한 대안
파일·URL·텍스트를 별도 페이지나 탭으로 분리하는 방식, 오류 항목 하나 때문에 정상 항목의 제출까지 차단하는 방식, 직접 텍스트의 무제한 입력, 브라우저 로컬 또는 서버 자동 초안 저장, 추출·분석에 부정확한 예상 퍼센트를 표시하는 방식, 자동 처리가 끝날 때까지 사용자를 입력 화면에 머물게 하는 방식, 변경된 원문을 기존 항목의 재시도로 처리하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
Step 2는 실제 형식 식별, 인코딩·텍스트 무결성, 구조적 처리 가능성, 안전성, 정확 중복과 검증 결과를 설계한다. Step 3은 IntakeSubmission·Source Item·OriginalAsset·Attempt·Audit 레코드, 접수 완료 트랜잭션, 전체 취소 전량 폐기, 종결 상태 이후 삭제와 상태 복원 계약을 구체화한다. 실제 시각 디자인과 반응형 세부 구현은 제품 UI 설계에서 다루고, 저장 이후 활용·재처리 화면은 Phase 6에서 다룬다.
### 미결사항
Section 1.9의 정책 수준 미결사항은 없다. 화면 이탈 경고의 브라우저별 한계, 상태 코드 내부 명칭, 진행률 이벤트 전송 방식과 재접속 상태 동기화 구현은 후속 기술 설계에서 확정한다.
