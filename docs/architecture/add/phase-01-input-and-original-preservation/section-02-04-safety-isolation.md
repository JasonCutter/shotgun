회의 상태: 완료

### 확정 결정
1. Step 2 검증과 Step 4 추출에서 다루는 모든 입력은 출처·확장자·사용자 설명·바이러스 검사 결과와 관계없이 비신뢰 자료로 취급한다. Office·브라우저·PDF 뷰어·스프레드시트 계산 엔진을 실행하지 않고 형식별 읽기 전용 파서로 구조와 데이터를 확인한다.
2. 검증·추출은 비신뢰 자료 전용 격리 프로세스 또는 컨테이너에서 수행한다. 기본 외부·내부 네트워크 접근, 호스트 파일시스템·사용자 홈·클라우드 자격 증명·데이터베이스 자격 증명·인스턴스 메타데이터 접근을 금지한다. 원본은 읽기 전용, 임시 영역은 실행 불가로 두며 비관리자 권한·최소 시스템 호출·하위 프로세스 금지·임시 자료 정리를 적용한다. 샌드박스 탈출 징후와 런타임 격리 실패는 안전 통과로 간주하지 않고 INDETERMINATE와 보안 사고 후보로 기록한다.
3. 모든 파서·컨테이너·이미지 디코더에는 시간·CPU·메모리·임시 디스크·열린 스트림·중첩 깊이·객체 수 제한을 둔다. 한도 초과는 원본 손상으로 단정하지 않고 RESOURCE_LIMIT_EXCEEDED로 차단한다. 구체적인 수치는 구현 검증과 운영 환경에 따라 조정 가능한 설정값이며 정책 자체로 고정하지 않는다.
4. OOXML·MHTML 등 허용된 컨테이너는 엔트리 수·중첩·단일 엔트리 크기·총 확장 크기·압축 확장 비율을 제한한다. 절대 경로, 상위 경로 이동, 중복 경로, 심볼릭 링크 유사 항목, 크기 불일치, 겹치는 데이터 영역과 비정상 중앙 디렉터리는 차단한다. 압축 폭탄 의심은 CONTAINER_BOMB_SUSPECTED로 기록하며 일반 ZIP·RAR·7Z 입력 지원으로 확대하지 않는다.
5. 악성코드 검사는 안전 판단의 한 신호로 사용하되 미탐지를 안전 보증으로 해석하지 않는다. 명확한 탐지는 MALWARE_DETECTED로 차단하고 검사 엔진 장애·서명 갱신 실패·검사 불가능은 SCAN_INDETERMINATE와 INDETERMINATE로 처리한다. 엔진·버전·서명 버전·검사 시각과 결과를 기록한다.
6. 안전성 처리 상태는 초기 격리 상태 QUARANTINED와 판정 상태 SAFE, SAFE_WITH_RESTRICTIONS, BLOCKED, INDETERMINATE, NOT_APPLICABLE로 구분한다. 여러 위험 사유가 있으면 하나로 덮어쓰지 않고 복수 reason code를 보존하며 Section 2.7이 다른 검증 결과와 통합한다.
7. 모든 원본과 파생 스냅샷은 Step 2 판정이 끝날 때까지 격리한다. SAFE와 SAFE_WITH_RESTRICTIONS만 후속 처리할 수 있다. BLOCKED와 INDETERMINATE 자료는 자동 미리보기·렌더링·다운로드·재처리를 수행하지 않는다. 같은 원본의 재검사는 새 Attempt로 남기며 격리 원본의 저장 기간·암호화·삭제·Audit 트랜잭션은 Step 3에서 확정한다.
8. URL 제출의 네트워크 접근은 문서 파서와 분리된 전용 fetcher만 수행한다. http·https와 표준 80·443 포트만 허용하고 [localhost](http://localhost), loopback, 사설망, link-local, CGNAT, multicast, reserved·documentation·benchmark 대역, IPv4-mapped IPv6와 클라우드 메타데이터 주소를 차단한다. DNS 해석 결과 중 하나라도 금지 대역이면 연결하지 않으며 연결 직전에 목적지를 다시 검증해 DNS rebinding을 방어한다. 사용자 지정 Host·Cookie·Authorization·클라이언트 인증서·임의 헤더는 전달하지 않는다.
9. URL 리디렉션은 홉 수를 제한하고 매 홉마다 scheme·host·port·DNS·IP를 다시 검증한다. 공개 도메인 간 이동과 단축 URL은 허용할 수 있지만 전체 리디렉션 체인을 기록한다. HTTPS에서 HTTP로의 강등, 자격 증명이 포함된 URL, 순환, 비HTTP scheme, 금지 네트워크로의 전이는 차단한다. 응답 크기와 압축 해제 크기·연결·읽기·전체 시간을 제한한다.
10. DOCX·XLSX·PPTX 매크로 확장 형식은 정식 지원하지 않는다. 지원 확장자 내부에서 VBA·ActiveX·실행 가능 OLE·실행 파일·매크로 관계가 발견되면 차단한다. 외부 템플릿·이미지·데이터 연결·DDE·외부 워크북은 자동 접근하지 않는다. 외부 의존 없이 정적 주 콘텐츠가 완전하면 SAFE_WITH_RESTRICTIONS로 통과할 수 있으나 의미 있는 처리가 외부 의존에 필수적이면 차단한다. 수식은 실행·재계산하지 않고 수식 문자열과 저장된 캐시값을 분리한다.
11. PDF의 JavaScript, OpenAction, Additional Action, Launch, RichMedia, 3D, 외부 실행, 자동 제출 폼을 실행하지 않는다. Launch와 실행 가능 첨부·악성 페이로드는 차단하고 단순 링크·URI는 기록만 하며 방문하지 않는다. JavaScript가 있어도 정적 페이지가 독립적으로 읽히면 제한 통과할 수 있다. 첨부 파일은 자동 추출·실행하거나 자동 Source Item으로 만들지 않으며 실행 파일·알 수 없는 위험 바이너리 첨부는 차단한다. 폰트·ICC 프로파일은 로컬의 제한된 파서로만 처리한다.
12. HTML·MHTML의 JavaScript·이벤트 핸들러·WebAssembly·플러그인·iframe·object·embed·폼·service worker를 실행하지 않는다. 외부 링크·이미지·CSS·폰트·iframe·API를 가져오지 않는다. 정적 본문이 독립적으로 존재하면 제한 통과할 수 있으며 JavaScript 전용 페이지는 ‘정적 본문 확보 불가’로 기록하되 그 사실만으로 악성으로 단정하지 않는다. MHTML 각 파트를 개별 검사하고 실행 가능 스크립트·패키지·위험 바이너리는 차단한다. data·blob 자원은 허용 MIME·크기·바이트 검사를 통과한 정적 자원만 데이터로 다룬다.
13. XML의 외부 엔티티·외부 DTD·XInclude·스키마 URL 다운로드와 네트워크 해석을 비활성화한다. DOCTYPE 존재와 엔티티 선언을 기록하되 외부·파라미터 엔티티를 해석하지 않는다. 의미 있는 본문 생성이 외부 엔티티 확장에 의존하면 외부 의존성으로 차단한다. 내부 엔티티도 개수·확장 문자 수·중첩 한도를 적용한다. SVG는 초기 지원 이미지 형식이 아니며 HTML·MHTML 안에서는 정적 자원으로 제한 처리하거나 후속 본문에서 제외한다.
14. YAML은 YAML 1.2 계열의 safe loader만 사용하며 사용자 정의 태그·클래스·생성자와 임의 객체 생성을 금지한다. 별칭 수·확장 노드 수·깊이를 제한하고 순환·한도 초과·중복 키는 차단한다. 기본 안전 타입으로 해석할 수 없는 태그는 지원하지 않는 능동 구조로 처리한다.
15. JSON에는 깊이와 전체 노드 수 제한을 적용한다. CSV와 스프레드시트의 셀이 `=`, `+`, `-`, `@` 또는 숨은 탭·캐리지리턴 뒤 수식 패턴으로 시작하면 FORMULA_INJECTION_RISK를 기록한다. 입력 단계에서 값을 수정하지 않고 문자열 그대로 보존한다. XLSX 수식·DDE·외부 데이터는 계산·재계산·새로 고침하지 않으며 수식과 저장된 값은 별도 필드로 유지한다. 내보내기 시 중립화 정책은 Phase 6 Step 20에서 결정한다.
16. PNG·JPEG·WebP는 최대 치수·총 픽셀·디코딩 메모리·애니메이션 프레임·총 프레임 픽셀 예산을 제한한다. 메타데이터·ICC 프로파일은 제한된 크기로만 읽고 외부 참조를 따라가지 않는다. 과도한 치수·청크 반복·디코딩 폭탄 패턴은 차단하며 선택적 메타데이터 파서 실패는 주 이미지가 안전하고 완전할 때만 경고 통과할 수 있다. OCR은 Section 2.4에서 수행하지 않는다.
17. zero-width, bidi, variation selector 등 Unicode 표시 제어 문자를 삭제하거나 정규화하지 않고 종류·논리 위치·개수를 기록한다. 코드·URL·파일명·식별자에서 방향 제어로 시각적 해석을 속일 가능성이 있으면 DISPLAY_SPOOFING_RISK를 기록한다. 형식 판정과 파일 식별은 화면에 보이는 문자열이 아니라 논리 원본 이름과 바이트를 사용한다. 자연어 본문은 표시 제어 문자가 있다는 이유만으로 자동 차단하지 않지만 명백한 기만 가능성은 제한 또는 차단 사유가 될 수 있다.
18. API 키·암호·개인정보·금융·의료정보 등은 악성 여부와 분리된 sensitivity_findings로 관리한다. 개인용 Shotgun은 민감정보 존재만으로 자동 거부하지 않지만 로그·오류·Telemetry에 원문 값을 남기지 않고 미리보기·검색·내보내기에서 마스킹 또는 보호를 적용한다. 민감정보 탐지는 오탐 가능한 후보이며 Canonical Fact로 자동 승격하지 않는다. 원문·URL·비밀값을 외부 보안·평판 서비스에 자동 전송하지 않는다.
19. 초기 보안 검사는 로컬 또는 self-hosted 파서·악성코드 엔진·격리 환경을 우선한다. 외부 평판·샌드박스·파일 검사 서비스로 원본 파일이나 비공개 URL을 자동 업로드하지 않는다. 같은 원본의 결정적인 위험 결과는 같은 엔진으로 자동 반복하지 않으며 인프라 장애나 검사기·서명 버전 변경에 따른 재검사는 새 Attempt로 남긴다. 새 검사에서 SAFE가 BLOCKED로 변경되면 이후 자동 사용을 중단하고 영향 범위를 기록하며 이미 Canonical에 반영된 지식의 처리 정책은 공통 보안·이력 설계에서 별도 확정한다. 수정·정화·재저장된 파일은 새 Source Item이다.
20. Section 2.4 출력에는 안전성 상태와 reason code, 격리 시각, 샌드박스·정책 버전, 악성코드 엔진·서명·결과, 네트워크 시도와 차단, URL DNS·IP·port·redirect chain, 사용 자원과 한도, 컨테이너 확장 통계, 매크로·스크립트·외부 관계·첨부·수식 위험, XML·YAML·Unicode·이미지 위험, 민감정보·로그 마스킹 상태, 제한 통과 시 제외 기능과 콘텐츠 영향, 다음 Section 진행 가능 여부와 사유를 포함한다. 이 결과는 검사기 버전에 종속된 재생성 가능한 검증 산출물이며 원본을 대체하지 않는다.

### 구현 후보값·운영 설정
다음 수치는 승인된 정책을 만족하기 위한 초기 후보값이며 구현 검증·배포 환경·관찰 결과에 따라 변경할 수 있다. 수치 조정만으로는 정책 변경으로 보지 않지만 변경 이유와 측정 결과는 구현 기록에 남긴다.
- 공통: wall-clock 30초, CPU 30초, 메모리 512MB, 임시 디스크 1GB, 열린 스트림 256개, 하위 프로세스 금지, 파서 깊이 100.
- 컨테이너: 엔트리·MIME 파트 10,000개, 중첩 3단계, 총 확장 500MB, 단일 엔트리 100MB, 확장 비율 100배.
- URL: 응답 본문 최대 50MB, 리디렉션 최대 5회, 포트 80·443. 연결·읽기·전체 timeout의 정확한 값은 구현 검증에서 정한다.
- YAML: 별칭 100개, 확장 노드 100,000개, 깊이 100.
- JSON: 깊이 100, 전체 노드 1,000,000개.
- 이미지: 한 변 30,000px, 총 100MP, 디코딩 메모리 512MB, 애니메이션 WebP 500프레임과 별도 총 프레임 픽셀 예산.
### 결정 근거
Shotgun은 사적인 원본·URL·자격 증명을 포함할 수 있는 비신뢰 자료를 자동 처리한다. 일반 애플리케이션 실행이나 네트워크가 열린 파서는 매크로·스크립트·외부 참조·SSRF·압축 폭탄·디코딩 폭탄이 시스템과 내부 네트워크에 영향을 줄 수 있다. 비실행·무네트워크 격리와 형식별 제한, 안전성 상태와 영향 기록을 결합하면 위험 요소를 실행하지 않으면서 정적 주 콘텐츠를 최대한 보존할 수 있다. 보안 검사와 민감정보 탐지를 콘텐츠의 사실성·신뢰도 판단과 분리해 Claim·Fact 검증 경계를 유지한다.
### 제외한 대안
Office·브라우저·PDF 뷰어·계산 엔진을 직접 실행하는 방식, 문서 파서에 일반 네트워크 접근을 허용하는 방식, 외부 관계·스크립트·수식을 자동 실행·갱신하는 방식, 위험 요소를 삭제한 정화본을 새 원본처럼 사용하는 방식, 악성코드 미탐지를 안전 보증으로 사용하는 방식, 비공개 원본·URL을 외부 평판·샌드박스 서비스에 자동 전송하는 방식, 민감정보 발견만으로 개인용 입력을 전면 거부하는 방식과 모든 범용 보안 기능을 Shotgun 전용으로 재구현하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
Section 2.5는 원본 바이트 기반 정확 중복을 검토한다. Section 2.6은 기존 자료 재사용·새 입력 맥락·관계 의도·취소의 사용자 선택을 정한다. Section 2.7은 Section 2.1\~2.6 상태와 reason code를 최종 상태·오류·재시도·사용자 메시지에 연결하고 Section 2.8은 Step 2 출력 계약을 확정한다. Step 3은 격리 원본·검증 산출물·Attempt·Audit의 저장 기간, 암호화, 삭제와 상태 복원 계약을 확정한다. Step 4는 제한 통과 자료의 실제 추출과 제외 요소의 Source Map·영향 표시를 구현한다. Phase 6 Step 20은 CSV·스프레드시트 수식 주입을 고려한 외부 내보내기 중립화 정책을 확정한다.
### 미결사항
Section 2.4의 정책 수준 미결사항은 없다. 실제 샌드박스·컨테이너 기술, 파서·디코더·악성코드 엔진과 버전, 서명 갱신 방식, timeout과 각 자원 한도 수치, OOXML·PDF의 위험 관계·첨부 판정표, 외부 의존성의 제한 통과 기준, 민감정보 탐지기·마스킹 방식, 검사 결과가 사후 변경됐을 때 이미 생성된 지식에 미치는 영향은 구현 검증과 Section 2.7\~2.8·Step 3의 후속 설계에서 확정한다.
