회의 상태: 완료
결정일: 2026-07-16
승인 방식: Phase 1 잔여 설계회의 준비안의 권장안 일괄 승인
### 확정 결정
1. 정확 중복 발견 시 사용자는 기존 자료 재사용, 새 입력 맥락으로 등록, 기존 문서와의 관계 의도 기록, 취소 중 하나를 선택한다. 사용자 선택 전에는 해당 항목을 Step 3로 넘기지 않는다.
2. 기존 자료 재사용은 새 검증·처리 없이 접근 가능한 기존 OriginalAsset과 현재 정책·버전에서 유효한 처리 결과를 사용한다.
3. 새 입력 맥락 등록은 같은 원본 바이트를 복제하지 않고 기존 OriginalAsset을 참조하는 새 IntakeItem 또는 제출 발생 기록을 만든다. 현재 Phase 1 입력 정책에 따라 새 맥락에서 사용자가 직접 입력할 수 있는 값은 선택적 메모로 제한하고, 입력 단계 처리 지시 필드는 추가하지 않는다. 프로젝트·태그 연결은 지식화 이후 경계를 따른다.
4. 사용자는 정확 중복을 새 버전 후보 또는 관련 자료라고 표시할 수 있지만 이는 관계 의도 후보일 뿐이다. Stable Source 동일성과 SourceVersion 생성은 Phase 2 Step 5.7에서 판정한다.
5. 기존 결과 재사용은 사용자가 기존 자산에 접근 가능하고, 기존 자산이 BLOCKED·QUARANTINED·INDETERMINATE가 아니며, 필요한 정책·검사기·변환기 버전과 현재 접근·민감도 정책을 만족할 때만 허용한다. 조건이 맞지 않으면 OriginalAsset만 재사용하고 필요한 단계부터 새 Attempt를 실행한다.
6. 기본 권장 선택은 비용과 위험이 가장 낮은 기존 자료 재사용으로 표시한다. 새 메모나 별도 접수 맥락이 필요하면 새 입력 맥락 등록을 명확히 구분하고 각 선택이 처리 비용·결과 재사용·Provenance에 미치는 영향을 설명한다.
7. 복수 자료 제출에서는 중복 항목별 개별 선택을 허용한다. 동일 조건의 여러 항목에 일괄 적용할 수 있지만 대상 수와 범위를 보여주며, 선택 대기 항목만 ACTION_REQUIRED로 멈추고 다른 정상 항목은 계속 진행한다.
8. 선택 결과에는 선택 유형, 시각·행위자, 참조 OriginalAsset·IntakeItem, 재사용 결과, 새로 실행할 단계, 선택적 사용자 메모, 관계 의도와 취소 사유를 기록한다.
### 결정 근거
같은 바이트를 새 물리 원본으로 복제하지 않으면서도 사용자의 새로운 접수 맥락과 의도를 보존해야 한다. 정확 중복과 문서 버전 관계를 분리하면 Phase 1이 성급하게 Stable Source 관계를 확정하지 않는다.
### 제외한 대안
모든 중복을 자동 건너뛰는 방식, 사용자 선택만으로 새 물리 OriginalAsset을 만드는 방식, 같은 바이트를 즉시 새 SourceVersion으로 만드는 방식, 입력 단계에 프로젝트·태그·처리 지시 필드를 다시 도입하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
Section 2.7은 ACTION_REQUIRED를 포함한 최종 상태·오류·재시도 계약을 확정한다. OriginalAsset 재사용과 새 IntakeItem 생성은 Section 3.1, 접근 경계는 Section 3.5, 멱등 실행은 Section 3.6에서 구체화한다.
### 미결사항
정책 수준 미결사항은 없다. 중복 선택 화면의 문구·일괄 적용 UX와 기존 결과 유효성 판정 캐시 구현은 후속 UI·구현 계획에서 확정한다.
