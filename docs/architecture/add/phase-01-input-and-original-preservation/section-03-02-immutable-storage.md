회의 상태: 완료
결정일: 2026-07-16
승인 방식: Phase 1 잔여 설계회의 준비안의 권장안 일괄 승인
### 확정 결정
1. OriginalAsset의 원본 바이트는 생성 후 덮어쓰기·부분 수정·정화·재인코딩하지 않는다. 파일명·표시 제목·메모·접근 정책은 별도 메타데이터로 관리하고 수정된 파일은 새 OriginalAsset 후보로 제출한다.
2. 저장 키는 원본 콘텐츠 해시와 알고리즘 버전에 결속하는 내용 주소화 원칙을 따른다. 같은 바이트는 하나의 물리 객체를 공유할 수 있지만 각 IntakeItem의 논리 이력은 유지한다. 저장 경로는 외부 API 식별자나 사용자 표시 ID로 노출하지 않는다.
3. 원본 승격은 임시 객체 해시·길이 재검증, 최종 저장소 쓰기 또는 기존 객체 확인, 저장 객체 체크섬 검증, OriginalAsset 생성 또는 연결, IntakeItem 상태 갱신과 Audit 기록의 순서를 원자적으로 보장한다. 중간 실패를 완료로 표시하지 않는다.
4. 원본 읽기 시 저장 객체의 길이와 체크섬을 검증할 수 있어야 한다. 불일치는 일반 문서 오류가 아니라 저장 무결성 사건으로 격리하고 후속 처리를 중단한다.
5. 원본은 저장 시 암호화된 저장소를 사용하고 암호화 키와 애플리케이션 데이터 접근 권한을 분리한다. 로그·오류·활동 기록에 원본 바이트나 비밀값을 복제하지 않는다.
6. 썸네일, 디코딩 텍스트, 정규화 문서, 구조 인덱스와 캐시는 OriginalAsset과 분리된 파생 자산이다. 파생 자산은 원본·변환기 버전·생성 Attempt를 참조하고 원본으로 승격하지 않는다.
7. 검증된 객체 저장소 또는 로컬 내용 주소화 저장 계층을 사용하며 Shotgun이 파일 시스템·오브젝트 스토리지 엔진을 새로 만들지 않는다. 저장 제품·멀티파트·서버측 암호화·체크섬 API 세부는 구현 검증 후 정한다.
### 결정 근거
내용 주소화와 쓰기·읽기 체크섬 검증은 원본 불변성과 중복 저장 효율을 함께 보장한다. 범용 저장 엔진은 기존 구현을 재사용하고 Shotgun은 승격 트랜잭션과 정책 결속에 집중한다.
### 제외한 대안
가변 파일 경로에 원본을 덮어쓰는 방식, 파생 산출물을 원본 파일 내부에 삽입하는 방식, 저장 엔진을 Shotgun 전용으로 재구현하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
Section 3.7은 정상·임시·격리·파생 자산의 보존과 삭제를 정한다. 구체 저장소 선정과 성능 수치는 구현 계획에서 확정한다.
### 미결사항
객체 저장소 제품, 로컬 개발 저장 방식, 암호화 키 관리, 대용량 업로드와 무결성 점검 주기는 구현 검증 대기다.
