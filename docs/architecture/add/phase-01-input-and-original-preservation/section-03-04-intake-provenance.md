회의 상태: 완료
결정일: 2026-07-16
승인 방식: Phase 1 잔여 설계회의 준비안의 권장안 일괄 승인
### 확정 결정
1. 최소 Provenance에는 제출자 또는 시스템 행위자, 서버 접수 시각과 사용자 제공 자료 시각, 입력 채널과 MaterialKind, 원래 파일명·제출 URL, Submission·IntakeItem·OriginalAsset·Attempt 식별자, 검증 정책·검사기·계약 버전, 중복 판정·사용자 선택, 선택적 사용자 메모, 적용된 표준 정책·User Directive 참조, 접근·민감도 기본값을 포함한다.
2. 서버가 관찰한 접수 시각·해시·채널은 시스템 관찰값으로 기록한다. 사용자가 제공한 작성자·화자·자료 날짜·출처가 있는 경우 사용자 주장으로 구분하며 외부 문서에서 읽은 값은 Phase 2의 추출 후보일 뿐 확정 사실로 승격하지 않는다.
3. 원본 해시, 최초 접수 시각, 최초 입력 채널, 최초 제출 값과 Attempt 이력은 덮어쓰지 않는다. 표시 제목·선택적 사용자 메모와 지식화 이후 프로젝트·태그 연결은 수정 가능하지만 변경 이력을 남긴다.
4. Phase 1 입력 단계에는 자료별 처리 지시가 없으므로 빈 지시를 만들어 저장하지 않는다. 표준 처리 정책 또는 이후 승인된 User Directive가 실제로 적용된 경우 참조 ID와 적용 버전을 스냅샷으로 보존한다.
5. 접수, 검증 시작·완료, 중복 선택, 원본 승격, 메타데이터 변경, 접근 정책 변경, 삭제 요청과 복구를 append-only 이벤트로 기록한다. 현재 상태는 이 이벤트에서 파생 가능한 투영으로 관리한다.
6. 모든 이벤트에는 행위자·시각·대상·이유·정책 버전을 기록한다. 일반 로그·오류·텔레메트리에 원문, 비밀번호, API 키와 민감한 개인 식별값을 복제하지 않는다.
7. 사용자 화면에는 이해 가능한 활동 이력과 출처 요약을 보여주고 내부 해시·저장 키·정책 버전·기술 오류는 권한 있는 상세 화면으로 분리한다. 원본 Provenance와 AI 생성 설명을 혼합하지 않는다.
### 결정 근거
시스템 관찰값, 사용자 주장과 AI 추출 후보를 구분해야 Claim과 Fact 경계가 Phase 1부터 흐려지지 않는다. append-only 사건 기록은 과거 처리 조건과 변경 이유를 재현하게 한다.
### 제외한 대안
현재 값만 덮어쓰는 메타데이터 테이블, 사용자 주장과 시스템 관찰값을 같은 필드로 합치는 방식, 원문 전체를 일반 로그에 복제하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
Section 3.5는 접근·민감도 변경과 상속을, Section 3.6은 상태 이벤트와 Attempt를, Phase 3\~4는 추출 후보의 Claim·Fact 승격 경계를 확정한다.
### 미결사항
이벤트 스키마, 현재 투영 생성 방식, 로그 마스킹 라이브러리와 보존 기간은 구현 계획에서 확정한다.
