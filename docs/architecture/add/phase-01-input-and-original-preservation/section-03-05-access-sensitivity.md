회의 상태: 완료
결정일: 2026-07-16
승인 방식: Phase 1 잔여 설계회의 준비안의 권장안 일괄 승인
### 확정 결정
1. 접근 범위는 누가 읽고 처리할 수 있는지를, 민감도는 어느 정도 보호와 표시 제한이 필요한지를 나타내는 독립 축으로 저장한다.
2. Section 1.7의 입력 최소화 원칙에 따라 사용자가 입력 화면에서 접근 범위·민감도를 직접 선택하지 않는다. 초기 기본 접근 범위는 개인 비공개이며 민감도는 시스템 기본값과 Section 2.4의 sensitivity_findings 후보를 통해 관리한다.
3. OriginalAsset의 접근 범위와 민감도는 이를 참조하는 IntakeItem과 파생 산출물의 최소 보호 기준이다. 파생 결과가 원본보다 덜 제한적인 범위로 자동 완화되지 않는다. 여러 원본을 결합한 결과는 입력 중 가장 제한적인 정책을 기본 상속한다.
4. 같은 OriginalAsset을 여러 IntakeItem이 참조할 때 작업 맥락별로 더 제한할 수 있지만 IntakeItem이 원본보다 넓은 권한을 부여하지 못한다. 공유 범위 확대는 원본 정책 변경 또는 승인된 별도 공유 투영을 요구한다.
5. 접근 범위 확대와 민감도 완화는 명시적 사용자 행동과 영향 확인을 요구한다. 변경 전후 값, 행위자·시각·이유와 영향을 Audit에 기록한다. 권한 축소는 조회·Job·검색·미리보기·캐시·내보내기에 재적용한다.
6. 중복 인덱스는 권한 확인 전에 기존 자산의 세부 정보를 노출하지 않는다. 물리 중복 제거와 논리 접근 권한 검사를 분리한다.
7. 모든 원본 읽기, 파생 작업, 검색 인덱싱, 미리보기, 내보내기와 외부 행동 전에 접근 정책을 검사한다. 백그라운드 Job과 Agent도 사용자와 동일한 정책 경계를 따른다.
8. sensitivity_findings는 보호 강화 제안과 경고에 사용하는 후보 신호이며 사용자·정책이 지정한 값을 자동으로 낮추거나 확정 사실로 덮어쓰지 않는다. 탐지기 버전과 오탐 가능성을 기록한다.
### 결정 근거
접근 권한과 콘텐츠 민감도를 분리하고 더 제한적인 정책을 상속하면 원본·중복·파생 처리 과정에서 정보가 조용히 넓은 범위로 유출되는 것을 막을 수 있다.
### 제외한 대안
입력 화면에서 복잡한 권한·민감도 선택을 요구하는 방식, 파생 결과를 기본 공개로 만드는 방식, 중복 판정 전에 기존 자산 정보를 노출하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
조직 역할·외부 공유·승인된 공유 투영은 후속 접근 제어 설계로 연기한다. Phase 6 내보내기와 외부 Action은 동일한 정책 게이트를 상속한다.
### 미결사항
인증·인가 제품, 정책 평가 계층, 검색·캐시 무효화 구현, 민감도 분류 체계와 조직 공유 모델은 구현·후속 설계 대기다.
