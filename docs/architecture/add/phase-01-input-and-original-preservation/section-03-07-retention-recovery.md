회의 상태: 완료
결정일: 2026-07-16
승인 방식: Phase 1 잔여 설계회의 준비안의 권장안 일괄 승인
### 확정 결정
1. 자산 등급을 정상 OriginalAsset, TemporaryIntakeBlob, QuarantineAsset, 재생성 가능한 파생 캐시로 분리한다. 정상 원본은 사용자가 삭제할 때까지 보존하고 임시·격리·캐시는 별도 제한 정책을 적용한다. 구체 보존 기간 수치는 운영 설정 후보로 관리한다.
2. 삭제는 즉시 접근 차단과 논리 삭제 표시, 참조 관계·파생 결과·Canonical 영향·내보내기 영향 계산과 사용자 확인, 복구 가능 기간 종료 후 원본 객체·파생물·검색 인덱스·캐시의 물리 삭제 순서로 수행한다.
3. 하나의 OriginalAsset을 여러 IntakeItem이 참조하면 한 맥락 삭제가 원본 전체 삭제를 의미하지 않는다. 마지막 허용 참조를 삭제할 때 원본 삭제 여부를 별도로 확인하고 물리 중복 제거 객체는 모든 참조와 보존 정책을 확인한 뒤에만 삭제한다.
4. ADR-002의 IntakeSubmission 전체 취소는 해당 제출에서 새로 생성한 원본·파생 결과에 대한 별도 즉시 폐기 계약이다. 기존·공유 OriginalAsset은 삭제하지 않으며 최소 Audit 증거는 보존한다.
5. BLOCKED·MALWARE_DETECTED·안전성 INDETERMINATE 원본은 일반 OriginalAsset 영역과 논리·권한상 분리된 QuarantineAsset으로 제한 보존하거나 정책에 따라 폐기한다. 자동 미리보기·다운로드·외부 전송·검색 인덱싱·Phase 2 처리와 무조건 재처리를 금지한다.
6. 격리 재검사는 정책·검사기·서명 DB 갱신 또는 명시적 사용자 요청에 따른 새 Attempt로만 수행하며 외부 보안 서비스 자동 전송 금지와 보안 차단 우회 금지 원칙을 유지한다.
7. 물리 삭제 후에도 삭제 수행을 증명하는 최소 Audit 이벤트, 비가역 식별자 또는 제한된 해시 정보, 시각·행위자는 보존할 수 있지만 삭제된 원문·제목·민감 메타데이터를 과도하게 남기지 않는다.
8. 백업은 암호화하고 원본과 동일한 접근 정책을 적용한다. 복구 시 삭제 tombstone과 권한 변경 이력을 먼저 재적용해 삭제된 자산이 활성 상태로 부활하지 않도록 한다.
9. 논리 삭제 후 운영 설정으로 정한 복구 가능 기간에는 사용자가 복구할 수 있다. 복구는 기존 OriginalAsset ID와 이력을 유지하고 보안 격리 복구는 일반 삭제 복구와 분리해 금지 정책을 자동 해제하지 않는다.
### 결정 근거
정상·임시·격리·캐시를 같은 보존 규칙으로 관리하면 위험 자료가 검색·미리보기에 노출되거나 삭제 자산이 백업에서 되살아날 수 있다. 참조 기반 삭제와 tombstone 우선 복구가 원본 공유와 삭제 의도를 함께 보호한다.
### 제외한 대안
모든 자산의 무기한 보존, 한 IntakeItem 삭제로 공유 원본 자동 삭제, 격리 자산의 일반 저장·미리보기, 삭제 이력 없이 즉시 물리 삭제, 백업 복구 후 삭제 상태를 나중에 적용하는 방식은 채택하지 않는다.
### 영향 범위와 후속 검토
법적 보존, 조직별 retention schedule, 다중 리전 재해복구, 구체 보존 일수와 백업 주기는 후속 운영 설계와 구현 계획으로 연기한다.
### 미결사항
정상·임시·격리의 초기 보존 기간 후보, 객체 저장소 lifecycle, 백업 제품·주기, 삭제 영향 계산과 Canonical 파생 투영 정리 절차는 구현 검증 대기다.
