## 19.1 위험도 분류 체계
위험도는 하나의 모델 점수가 아니라 독립된 축을 결합해 정책 상태로 산출한다.
평가 축:
- 읽기·쓰기·외부 공개 여부
- 대상과 청중의 범위
- 개인정보·민감정보·비밀정보
- 금전·계약·법률·의료·안전 영향
- 되돌릴 수 있음과 보상 가능성
- 자격 증명·권한·시스템 범위
- 자동화 반복성·규모·속도
- 오대상·중복·오정보의 피해
- 사용자의 명시적 Directive·위임
정책 등급:
- `R0_INFORMATIONAL`: 비공개 읽기·검색·일반 설명
- `R1_PRIVATE_DRAFT`: 비공개 초안·시뮬레이션·미리보기, 외부 상태 불변
- `R2_BOUNDED_REVERSIBLE_WRITE`: 범위가 좁고 되돌리기 쉬운 쓰기
- `R3_SENSITIVE_OR_MATERIAL`: 민감정보, 공개, 금전, 계약, 일정·파일·메시지의 중요한 변경
- `R4_PROHIBITED_OR_UNSUPPORTED`: 정책상 금지되거나 안전하게 수행할 수 없는 작업
등급은 낮추기 위한 평균이 아니라 가장 중요한 위험 축을 보존한다. 위험도가 불명확하면 낮게 추정하지 않는다.
## 19.2 분류 입력·정책
`RiskAssessment`는 다음 입력을 사용한다.
- 인증된 사용자·역할·프로젝트
- ResultArtifact·ActionCandidate revision과 digest
- 대상·수신자·공개 범위·외부 시스템
- 접근 범위·민감도·마스킹 결과
- 예상 side effect·비용·되돌리기·반복 횟수
- Connector capability와 현재 권한
- 활성 User Directive·ActionDelegationPolicy
- 법적·의료·재정·보안 등 도메인 표시
- 모델 불확실성·Gap·Conflict·Projection lag
AI는 의미 위험과 누락 가능성을 제안할 수 있지만 최종 필수 승인 규칙은 버전화된 결정적 정책 엔진이 적용한다. 시스템 안전 정책은 사용자 Directive와 위임보다 우선한다.
## 19.3 자동 제공 가능 범위
다음은 접근 권한과 Citation 정책을 통과하면 즉시 제공할 수 있다.
- 개인 범위의 검색·답변·요약
- 외부 상태를 바꾸지 않는 분석·비교·시뮬레이션
- 비공개 문서·이메일·메시지 초안
- 읽기 API 조회와 권한 내 내보내기 파일 생성
- ActionCandidate·Preflight·예상 영향 미리보기
- 사용자가 요청한 형식·문체 변환
자동 제공은 결과 전달만 의미하며 게시·전송·공유·저장소 변경을 포함하지 않는다. 민감정보가 포함된 결과는 개인 화면에서도 최소 표시·마스킹·다운로드 제한을 적용할 수 있다.
## 19.4 사용자 검토 필수 범위
다음은 실행 또는 외부 전달 전에 명시적 검토가 필요하다.
- 메일·메시지 발송, 일정 생성·변경, 파일 쓰기·이동·삭제
- 외부 사이트 게시·공개 링크·대규모 공유
- 민감정보·개인정보의 외부 전송
- 금전·계약·법률·의료·안전과 관련된 중대한 판단 또는 실행
- 되돌리기 어렵거나 보상 불가능한 작업
- 다수 대상·반복·대량 자동화
- Connector 권한 확대·자격 증명 변경
- 모델 불일치·근거 부족이 중요한 Action
검토 화면은 대상, 실제 전송·변경 내용, 위험·비용, 근거, 되돌리기, idempotency와 유효 시간까지 보여준다.
## 19.5 동의·사전 정책·위임
기본값은 쓰기 Action의 실행 직전 명시적 승인이다.
사용자는 제한된 `ActionDelegationPolicy`를 별도로 승인할 수 있다. 필수 범위:
- 허용 Action 유형·Connector·대상 범위
- 최대 횟수·기간·비용·데이터 민감도
- 허용 시간대와 제외 조건
- 미리보기·사후 알림·일시 중지 규칙
- 만료·회수·긴급 정지
- 정책 버전과 승인 이력
사전 위임은 `R2_BOUNDED_REVERSIBLE_WRITE` 중 충분히 제한된 작업에만 적용한다. 공개·금전·계약·의료·보안·민감정보·비가역·권한 확대 작업은 정책이 있어도 실행별 재승인을 요구할 수 있다. Action이 승인 당시 digest·대상·범위를 벗어나면 토큰은 무효다.
## 19.6 설명·경고·대안
검토가 필요한 경우 사용자가 행동을 이해할 수 있도록 다음을 제공한다.
- 검토가 필요한 구체적인 이유
- 실행 시 바뀌는 외부 상태와 대상
- 근거 부족·Conflict·민감정보·비가역성
- 예상 비용·시간·실패 가능성
- 안전한 대안: 초안만 생성, 읽기 전용 확인, 대상 축소, 민감정보 제거, 수동 실행
경고는 모호한 공포 문구가 아니라 실제 위험과 사용자가 취할 수 있는 조치를 설명한다. 승인 버튼을 누르도록 유도하기 위해 위험을 축소하거나 숨기지 않는다.
## 19.7 예외·상향 검토
사용자는 모든 작업의 위험도를 수동으로 높이고 추가 검토를 요구할 수 있다. 사용자가 낮추기를 요청해도 필수 안전·권한·법적 정책은 우회할 수 없다.
다음 경우 자동으로 상향한다.
- 위험 분류 불확실
- 대상 또는 외부 상태가 미리보기와 다름
- 승인 후 Action revision 변경
- Connector capability·권한 변경
- Projection·근거 stale
- 모델 간 중요한 불일치
- 반복 실행·대상 수·비용이 예상 한도 초과
정책 충돌이나 지원 불가 작업은 `BLOCKED` 또는 지정된 수동 경로로 보낸다. 하향 예외는 정책 소유자와 이유·기간·범위를 명시해야 한다.
## 19.8 판단 Audit·정책 버전
모든 `RiskDecision`은 다음을 기록한다.
- 입력 Result·Action revision과 digest
- 평가 축과 원시 사실
- 적용 정책·Directive·위임 버전
- AI 분석이 사용됐다면 provider·model·prompt·결론
- 최종 등급·자동 제공·검토·차단 결정
- 사용자 승인·거절·취소·만료
- 재평가 trigger와 이전 결정 관계
정책 변경은 과거 결정을 덮어쓰지 않는다. 실행 전에는 현재 정책으로 재검증하되, 사용자에게 승인 당시와 현재 정책의 차이를 보여준다.
