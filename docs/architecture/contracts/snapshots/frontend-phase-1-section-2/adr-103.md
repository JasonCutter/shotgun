## Decision

- Settings is a typed Project Policy control plane, not only a preference screen.
- Scope is Principal, Project, System, or Resource.
- Server `SettingsSnapshot`, `SettingDescriptor`, and Capability are authoritative.
- Application modes are `IMMEDIATE`, `CONFIRM_REQUIRED`, `REVIEW_REQUIRED`, `RESTART_REQUIRED`, `MIGRATION_REQUIRED`, `READ_ONLY`, and `UNAVAILABLE`.
- The frontend does not infer risk or application mode from field name, category, or role.
- Every write supports CSRF, idempotency, revision preconditions, and `OUTCOME_UNKNOWN` recovery.
- Project archive and delete are separate.
- Deletion, sensitivity lowering, retention shortening, credential revocation, hard budget, schema migration, directive, and fact-priority changes use high-risk flows.
- Directive, fact-priority, and Canonical semantics remain behind Proposal/Review boundaries.
- Connector secrets are masked and never stored or fully redisplayed by the browser.
- Existing Resource settings bind to the Resource Project rather than the active Project.

## 2026-07-24 clarification

- Ask defaults come from server Ask UI Policy `defaultAskMode`; `CANONICAL_MODE` is the fallback.
- Settings changes may increment `policyContextRevision` and detailed policy revisions.
- Current settings are not silently applied retrospectively to in-progress Resources.
- Current strengthened Privacy/Sensitivity policy is revalidated at sensitive action boundaries.
- Initial-MVP Settings drafts are excluded from route-outside restore and Home Continue Working.
