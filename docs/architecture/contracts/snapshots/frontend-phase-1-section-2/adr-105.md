## Decision

1. Important commands and long-running resources/attempts preserve the server-interpreted `FrontendPolicyContext`.
2. Context can include Project lifecycle, privacy, sensitivity, retention, model routing, budget, feature availability, and schema policy revisions.
3. Command acceptance returns `acceptedPolicyContext`; attempts preserve the context actually used.
4. Existing result meaning and provenance remain pinned to their creation context.
5. External providers/research/connectors, protected citations, copy, export, download, feedback, knowledge transition, retry, and Project archive/delete revalidate current policy and capability.
6. Policy strengthening can block, mask, or stop existing actions.
7. Policy relaxation does not automatically expand access to an existing resource.
8. Retrying the same context is distinct from rerunning under current settings.
9. The server may expose capabilities such as `RETRY_SAME_CONTEXT`, `RETRY_WITH_CURRENT_POLICY`, and `START_NEW_RUN_WITH_CURRENT_SETTINGS`.
10. The frontend does not infer retry meaning or policy effect from strings or field names.
