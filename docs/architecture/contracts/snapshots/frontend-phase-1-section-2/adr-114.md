# Snapshot — ADR-114 Project Administration and Settings Repository Ownership Boundary

- Source: `docs/architecture/adr/ADR-114-project-administration-and-settings-repository-ownership-boundary.md`
- Snapshot date: 2026-07-26
- Status: Accepted for Phase 1 Section 2 implementation; Canonical synchronization pending user approval

## Ownership

- Authentication owns Principal, Session, Membership, API Token, and authentication audit.
- Project Administration owns Project identity, metadata, lifecycle, and Project revision.
- Settings Policy owns Principal preference, Project/System/Resource settings, Settings revision, and Policy context.
- Frontend Command Gateway owns request validation, accepted contexts, semantic digest, idempotency, outcomes, and `clientRequestId` recovery.

## Coordinator boundary

Project creation is a principal-scoped administrative command. An application coordinator or explicit transaction adapter atomically creates the Project, owner membership, and initial settings/policy state without transferring schema ownership to the coordinator.

## Versioned writes and rollback

- State-changing operations use a versioned request with typed preconditions validated atomically.
- The server creates `commandId` and authority contexts.
- Application rollback disables new writes and keeps compatible readers.
- Production schema rollback uses forward corrective migrations, backup restore, or point-in-time recovery.
- Project tombstones, commands, audit, and revisions are preserved. Destructive schema drop is limited to explicit development/test reset.
