# Project Shotgun — 개발 전략 전면 재정립

**전략 재정립안 · Version 0.1**  
**작성 기준일:** 2026년 10월 10일  
**상태:** 검토용 전략 문서 (사용자 확정·공식 ADD/ADR 반영 전)  
**적용 범위:** Project Shotgun 및 현재 진행 중인 VP(Vampire) 지식 자동화 구현  
**문서 성격:** 기존 확정 설계의 대체본이 아닌, 목표·평가·실행 우선순위를 재정립하기 위한 제안

---

## 1. 경영 요약

Shotgun은 AI 모델의 관계 분류 성능을 높이기 위한 실험 프로젝트가 아니다. 사용자가 자료를 투입하고 질문하면 최신의 권한 있는 원문을 근거로, 주장 간 동의·조건 차이·충돌을 구별한 답변을 제공하는 **신뢰할 수 있는 개인 지식 운영체제**를 완성하는 프로젝트다.

최근 관계 추론 개선은 DeepSeek 프롬프트·출력 계약·Architecture A/B·SSC 등으로 반복되었다. 이 과정에서 운영 안정성과 증거 보존 방식은 발전했지만, 평가에 사용한 72쌍의 의미 정답이 독립적으로 승인됐는지는 확인되지 않았다. 따라서 기존 수치가 *동결된 후보 기준에 대한 성능*임은 말할 수 있어도 *객관적으로 확정된 의미적 정확도*라고 표현할 수는 없다.

**전략적 전환:** 제품 인수 결과 → 신뢰할 수 있는 평가 기준 → 실제 병목 증명 → 최소한의 기술 보완 → 후속 Gate 진입 순서로 작업한다. 필요성이 입증되지 않은 프롬프트·Schema·모델 교체 실험은 중단한다.

**즉시 우선 과제:** VP-05와 연계된 관계 평가 기준의 신뢰성을 회복하고, 남은 완료 조건을 실제 제품 시나리오와 연결해 판정할 수 있도록 한다. 기존 VP-06 STOP은 유지한다.

## 2. 기존 목표와 변경하지 않을 계약

### 2.1 최종 사용자 인수 시나리오

기준 문서 `vp-vampire-implementation-plan.md` §1에 명시된 최종 인수 시나리오를 변경하지 않는다.

1. 사용자는 빈 Shotgun에서 별도 프로젝트 설정 없이 자료 A를 한 번 투입하고 질문한다.
2. 이후 자료 B와 A의 수정본을 투입한 다음 동일한 질문을 다시 한다.
3. 두 번째 답변은 **현재 활성 SourceVersion**과 자료 B를 반영하고, 합의·조건 차이·충돌을 원문 인용 및 해당 시점과 함께 구분한다.
4. 처리 중 질문은 동일한 AnswerRun이 준비를 기다렸다가 자동으로 이어서 완료한다.
5. 지식 처리 실패 시 이유를 제시하며, 근거 없는 확정 답변을 생성하지 않는다.
6. 이 여정에서 후보 선택, 원문 선택, 지식 Review, 승인 등의 추가 사용자 결정은 요구하지 않는다.

이것은 **최종 제품 계약**이다. 개별 관계 라벨의 벤치마크 정확도가 이 계약을 대체할 수 없다.

### 2.2 불변 아키텍처 경계

- **AI 출력은 판단 후보**이다. Claim과 Fact를 구분하고, 출처 없는 진술을 검증된 사실로 승격하지 않는다.
- VP의 활성 지식 기록 권위는 현행 승인된 VP Ledger 설계를 따른다. 기존 Canonical 기록과 VP Ledger를 혼동하지 않는다. Compiled Truth/Projection은 재생성 가능한 파생 결과로 취급한다.
- SourceVersion, EvidenceSpan, 권한·민감도, 데이터 변경 이력과 replay 가능성을 유지한다.
- 실패·미해결·`OUTCOME_UNKNOWN`·비발행은 서로 다른 상태로 보존한다. 중복 유료 AI 호출이나 불명확한 재시도를 정당화하지 않는다.
- 확정된 ADD·ADR·기존 Gold·실험 이력·생산 정책은 조용히 덮어쓰지 않는다. 전략 변경은 영향 범위와 승인 근거를 기록한 뒤 반영한다.

## 3. 그동안의 문제를 어떻게 판단할 것인가

### 3.1 시간 낭비가 발생한 지점

| 관찰된 진행 | 문제의 핵심 | 재발 방지 원칙 |
|---|---|---|
| 프롬프트·Schema·출력 계약의 반복 변경 | 어떤 변경이 실제 제품 품질을 개선하는지 인과적으로 확인하기 어려움 | 실험 목적·성공 기준·회귀 위험을 먼저 고정 |
| 의미 정답의 승인 수준이 불분명한 상태에서 반복 채점 | 평가 기준의 결함과 모델 오류를 혼동 | 검증된 기준과 후보 기준을 별도 보고 |
| 높은 confidence와 엄격한 형식 검사에 집중 | 정확한 관계 발견과 잘못된 관계 차단을 하나의 점수로 혼용 | 의미 품질·구조 품질·발행 결과를 분리 |
| 새로운 아키텍처 제안이 연속 등장 | 제품 수준의 병목 증명보다 구현 방법 탐색이 선행 | 필요성 증명 없는 구조 교체 보류 |
| 상위 에이전트의 작업을 상세 구현 지시로 제한 | 자율적 문제 해결 및 기존 검증 결과 재사용이 저해될 수 있음 | 목표와 완료 기준만 명시 |

이 평가는 **개발 프로세스에 대한 진단**이다. 개별 AI 모델에 실패의 책임을 단정하거나, 과거 작업 전체를 무가치하다고 평가하지 않는다.

### 3.2 보존하고 재사용할 성과

- 실제 Sources → Claim/Evidence → VP Ledger → Ask로 연결된 부분적인 수직 경로 및 증분·재구축 검증.
- SourceVersion과 인용 근거의 고정, 권한 분리, 현재 epoch 및 watermark 관리.
- provider 실행 영수증, 글로벌 예산 통제, 유료 호출 중복 방지, 장애 시 `OUTCOME_UNKNOWN` fence.
- 실패 사례와 출력 원본이 해시로 동결된 평가 자료 및 재현 가능한 실험 증거.
- SSC가 밝힌 **형식적 일관성 검증과 의미적 정당성 검증의 차이**.

이 성과들은 제거 대상이 아니라, 후속 설계 변경 시 보호해야 할 자산이다.

### 3.3 현재 확인된 평가 리스크

2026년 10월 10일의 `reference-audit-report.md`에 따르면, 72개 평가 쌍 중 30개는 `CANDIDATE`이고 나머지 42개는 조사된 annotation 자료에서 독립 승인 기록이 확인되지 않았다. 이는 *72개가 모두 오답*이라는 뜻이 아니다.

세 사례는 방향이 필요한 `QUALIFIES`를 허용하면서 `NONE`만 정답 방향으로 기술했다. 또 일부 구형 허용 집합은 현행 의미 기준상 타당할 수 있는 `NO_RELATION`을 배제한다. 합성 점검에서는 관계 채택이 0건인데 방향 정확도가 100%인 출력도 재현했다. 따라서 **동결 평가 결과의 재현 가능성**과 **의미 정답의 신뢰성**을 분리해야 한다.

Architecture B 실호출은 계획한 36회 중 12회에서 중지됐다. JSON은 12/12 유효했으나 Schema 통과 7/12, 정확히 채택된 양성 2/7, critical recall 1/4였다. 다섯 건의 witness 길이 초과가 중지 사유였고 비방향 관계의 잘못된 화살표·과잉 `RELATED` 제안 등 추가 문제가 원본에서 관찰됐다. 이는 **해당 동결 평가 계약에 대한 결과**이지 독립적으로 인증된 보편적 모델 의미 오류율이 아니다.

## 4. 전략 전환의 원칙

1. **제품 우선:** 실제 두 동작 제품 여정과 증거의 질을 우선 평가한다.
2. **검증 우선:** 의미 정답의 승인 수준을 확인하기 전에는 모델의 ‘객관적 정확도’를 선언하지 않는다.
3. **원인별 분리:** 검색 누락, 근거 누락, 관계 종류 오류, 방향 오류, 출력 형식 실패, 채택 게이트 실패, 사용자 답변 오류를 분리한다.
4. **최소 변경:** 필요한 제품 오류가 검증된 경우에만 프롬프트·SSC·모델·관계 전략을 변경한다.
5. **측정 가능한 비용:** 정확도뿐 아니라 지연, 호출 수, 토큰, 청구 비용, 재시도·복구 비용, 관계 쌍 폭증을 고려한다.
6. **상위 에이전트 자율성:** 요청서는 목표·완료 기준·안전 경계만 제시하고 방법은 실행 에이전트에 맡긴다.
7. **기존 결정 존중:** 현행 지식 권위와 동결된 실험 결과를 보존하며 ADR/ADD를 통한 정식 변경 승인 전까지 새 설계를 운영에 도입하지 않는다.

## 6. 새로운 실행 로드맵

이 절의 단계는 **전략 실행 우선순위**이며, 기존 VP-01~VP-11의 고정 추적 ID나 VP-0~VP-4 제품 단계명을 대체하지 않는다. 기존 로드맵의 Gate와 의존성을 별도로 유지한다.

### 단계 A — 평가 기준의 신뢰성 확보

**목표:** 객관적으로 해석 가능한 관계 평가 체계를 마련한다.

**핵심 결과:** 후보·독립 검증·분쟁·문맥 부족 상태의 구분, 원문에 실제 제공된 문맥의 고정, 관계 종류/방향/근거의 가능한 복수 해석 관리, 신뢰할 수 있는 지표 분모.

**완료 판정:** 신뢰 가능한 평가 집합과 미검증 평가 집합을 구분하고, 승인되지 않은 정답은 인증 품질 지표에서 제외한다. 평가기 구조 검사와 의미 승인 절차가 구분된다.

### 단계 B — 사용자 여정 중심의 제품 진단

**목표:** 최종 제품 계약의 어느 부분이 실제로 동작하고 어느 부분이 실패하는지 증명한다.

**핵심 결과:** 자료 A → 질문 → B 추가 → A 수정 → 재질문 흐름에서 원문 인용, 활성 버전, 충돌·조건·시점, 지식 대기·재개, 오류 노출, 승인 클릭 횟수를 관측한다.

**완료 판정:** 실증된 기능과 미검증 기능을 나누고, 실패를 근거 검색·추론·원장 반영·출력 검증 등 원인별로 분해한다. 기존 VP-03 제품 Gate 자체를 조기에 완료 처리하지 않는다.

### 단계 C — 관계 처리 아키텍처의 필요성 재평가

**목표:** 제품 목표에 반드시 필요한 관계 처리만 남긴다.

**비교할 대안:** 현행 사전 관계 축적, 질문 시 필요한 관계 평가, 제한된 사전 관계 축적과 질문 시 비교의 혼합형.

**주의:** 질문 시 평가 방식은 **가설**이다. 기존 VP-2의 자동 관계 기록, 활성 지식 권위, 증분 재생 계약을 사용자 승인 없이 대체하지 않는다.

**완료 판정:** 각 접근의 제품 품질·검증 범위·재계산 일관성·지연·비용·보안 및 데이터 권위 영향을 비교해 유지·보완·전환 중 하나를 권고한다.

### 단계 D — 확인된 병목만 최소 수정·검증

**목표:** 앞선 단계에서 재현된 문제를 가장 단순하고 검증 가능한 방법으로 해결한다.

**핵심 결과:** 제품에 영향을 주는 실패를 기준으로 개선 목표를 명확히 하고 기존 기준선 대비 품질 향상과 회귀를 동시에 검증한다. 변경한 방식은 새로운 버전과 근거로 식별한다.

**완료 판정:** 독립적으로 신뢰 가능한 평가에서 개선 근거가 있으며, 비용·지연·실행 안정성 저하가 통제된다. 개선이 없으면 SSC나 모델 교체를 유지해야 할 이유도 없다.

### 단계 E — VP 잔여 Gate·출시 경로 복귀

**목표:** VP-04 품질·VP-05 규모/비용과 나머지 미완료 Gate를 기존 완료 조건에 따라 순차적으로 종료한다.

**조건:** VP-05의 완료 또는 정식 제한부 완료를 검토할 때에도 기존 `vp-completion-tracker.md`와 DoD가 요구하는 사항을 근거 없이 생략하지 않는다. VP-06/07 장애·복구, VP-08/09 형식·제품/보안, VP-03 최종 사용자 흐름, VP-10/11 공통 Gate·출시 인수는 승인된 의존성 순서대로 진행한다.

## 7. 품질·성공 지표의 재정의

| 차원 | 주요 관측 질문 | 부적절한 해석 방지 |
|---|---|---|
| 제품 품질 | 실제 질문에 인가된 최신 원문 근거로 답하는가? | 관계 라벨 정확도를 최종 답변 품질로 대체하지 않음 |
| 의미 품질 | 필요한 관계를 찾고 무관한 관계를 만들지 않는가? | 후보 Gold 일치를 객관적 의미 정답으로 주장하지 않음 |
| 방향 품질 | 올바른 관계를 채택했을 때 방향도 올바른가? | 채택이 0건이면 조건부 방향 정확도는 `N/A` |
| 근거 품질 | SourceVersion·EvidenceSpan·조건·시점이 일치하는가? | anchor 위치 유효성을 의미 근거 충분성으로 간주하지 않음 |
| 안정성 | 선언이 반복 일치하는가, 시스템 발행 상태가 일치하는가? | 원본 선언 안정성과 비발행 안정성을 분리 |
| 실행·비용 | 호출 수, p50/p95, 토큰, 실제 비용, 복구 비용은? | 형식 통과 또는 재시도 성공만으로 효율을 주장하지 않음 |
| 안전성 | 외부 전송·권한 누출·원장 중복·근거 없는 단정이 발생하는가? | 속도와 정확도를 위해 권한·원장 무결성을 완화하지 않음 |

**지표 보고의 공통 조건:** 정의와 분모, 평가 집합의 검증 상태, 실제 발행/비발행 여부, 미평가 비율, 신뢰 구간 또는 표본 한계를 함께 명시한다. 검증 대상이 0이면 정확도 100%를 보고하지 않는다. 기존 0.9 confidence gate는 보존하지만, 이 수치가 통계적으로 보정된 정답 확률이라는 가정은 별도로 검증해야 한다.

## 8. 역할·권한·의사결정 방식

| 주체 | 책임 | 결정 경계 |
|---|---|---|
| 사용자 | 제품 비전·중요 우선순위·전략 변경 승인 | 중요한 범위·권위·Gate 변경 최종 확정 |
| 상위 에이전트 | 조사·설계·OSS 검토·구현·검증·원인 분석·대안 선택 | 명시된 목표와 기존 안전 경계 안에서 방법을 자율 결정 |
| ChatGPT | 목표·완료 기준 설정, 결과물 독립 검토, 아키텍처 영향과 리스크 판정 | 세부 구현 통제보다 결과의 증거 수준과 진행 Gate 판단에 집중 |

**요청서 작성 규칙:** ‘왜, 무엇을 달성해야 하는가, 어떻게 성공을 판정하는가, 무엇을 보존해야 하는가’만 적는다. 파일별 수정 순서, 함수명, 테스트 케이스 구현법, 라이브러리 선택 등의 수단은 상위 에이전트의 재량으로 둔다.

**완료·실패 처리:** 목표 미달 시 작은 보정 지시를 끝없이 반복하기보다, 실패 원인·평가 기준·요구사항 자체를 재검토한다. 합의된 결정만 ADD에 반영하고 중요한 변경은 ADR로 관리한다. 실험 후보는 사용자 승인 전 Canonical/VP 운영 권위로 승격하지 않는다.

## 9. VP-05 즉시 실행 과제

**작업명:** VP-05 전략 재정립 및 평가 신뢰성 회복

**목표:** 관계 추론의 객관적 성능을 판정할 근거를 마련하고, 현재 구현을 유지·개선·전환할지 실제 제품 가치와 비용을 기준으로 결정할 수 있게 한다.

**필수 결과:**

- 기존 실험에서 **입증된 사실**과 **정답 기준의 불확실성으로 아직 판단할 수 없는 사항**의 구분.
- 평가 정답 신뢰성의 복구 방향과 승인 가능한 품질 측정 방식.
- VP-05의 규모·비용·관계 축소·정확성 관련 남은 완료 조건 및 실제 제품 영향을 연결한 판단 근거.
- v11·SSC·모델 교체·질문 시 관계 판단 중 필요한 것과 불필요한 것을 구분한 권고.
- VP-05 종료 가능성(`COMPLETE`, `COMPLETE_WITH_LIMITS` 적격성 또는 미완료)을 실제 승인된 Gate 기준으로 판정할 자료.

**권한:** 상위 에이전트가 목표 달성에 필요한 기술적 방법을 자율 선택한다. 외부 OSS/공식 문서/선행 사례도 필요 시 활용한다.

**승인 경계:** Gold-B-7 개봉, 운영 정책·생산 데이터 변경, 확정 ADD/ADR 변경, push/PR/merge, VP-06 진입은 별도 승인 대상이다. 원본 동결 실험·출처 기록은 변경하지 않는다.

**보고 형식:** 달성 여부, 검증 증거, 남은 위험, 제거·유지할 작업, 영향받는 Gate와 필요한 별도 승인만 간결히 보고한다.

## 10. 의사결정 현황 및 미결사항

### 10.1 이 문서에서 제안하는 결정

- 관계 정확도 향상 자체가 아니라 **근거 있는 최종 답변**을 제품 최우선 결과로 삼는다.
- 미승인 후보 Gold에 대한 점수를 확정 의미 정확도처럼 보고하지 않는다.
- SSC·모델 변경·대량 재실험은 실제 병목과 신뢰 가능한 비교 기준이 확인될 때까지 보류한다.
- 상위 에이전트에게 해결 방법의 자율성을 부여하고 요청서는 목표·완료 기준·안전 경계로 최소화한다.
- VP-05의 현재 중지·검토 상태를 유지하며 변경 근거가 갖춰지기 전에는 후속 Gate로 이동하지 않는다.

### 10.2 별도 검증·결정이 필요한 사항

- 72개 개발 비교 사례 중 독립 의미 승인 대상으로 선정할 범위와 승인 책임자.
- 제품용 질문/답변 평가 집합의 대표성·추출 품질과 관계 품질을 분리하는 방식.
- 사전 관계 축적과 질문 시 관계 판단의 제품·원장·비용 비교 및 계약상 변경 필요 여부.
- VP-05의 품질·규모·비용 Gate에 필요한 정식 종료 요건과 `COMPLETE_WITH_LIMITS` 허용 가능성.
- confidence 0.9의 보정성, 실측 청구 비용과 대량 관계 후보 축소 품질.

**현재 문서 상태:** 전략안을 정리한 것일 뿐, 위 미결사항을 자동 승인하거나 기존 권위 문서를 변경하지 않는다.
