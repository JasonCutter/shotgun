# Shotgun V1.0 — VP 완료 제품 기준선

## 결정과 게시 상태

- 결정일: **2026-10-20 KST**.
- 사용자 결정: README를 실제 현재 제품에 맞게 갱신하고, VP 완료 상태를 **V1.0**으로 명명한다.
- Application Version: **`1.0.0`**. 제품 표시명은 **Shotgun V1.0**이다.
- 작성 시점은 로컬 검증 완료/게시 전이다. GitHub README·버전 메타데이터의 Canonical 반영은 별도 PR/merge 승인을 따른다. 실제 게시 완료 여부는 GitHub PR·main·tag/Release의 readback으로 판정하며 이 문장의 과거 작성 상태로 대신하지 않는다. 작성 시점에 새 태그·GitHub Release는 생성하지 않았다.
- 정식 태그명은 **`v1.0.0`**으로 한다. 병합된 정확한 커밋과 사후 CI를 확인한 뒤 승인된 게시 절차로 생성한다.

기존 `v1.0` / “Shotgun v1.0”은 2026-09-16의 **Zero-Data Baseline**이며
`5ff2db454a46dc1fb6599d99f5d20ea912d4c877`을 가리킨다. 이번 VP 완료본과 다르다.
기존 태그를 강제로 옮기거나 과거 릴리스의 대상 커밋을 바꾸지 않는다. 향후 새 Release를
게시할 때 V1.0의 현재 제품 범위와 이 차이를 명시하고 새 `v1.0.0`을 최신 제품 릴리스로 지정한다.

## 완료된 제품 범위

- ADR-172의 VP Ledger·SourceVersion·Evidence를 통한 자료 투입 → 자동 지식화 → 질문.
- 사용자 개별 지식 검토/승인 없이 실제 application·worker·Ask를 사용한다.
- 원본과 변경 이력, 현재 버전의 검색·인용, 과거 AnswerRun의 원문·인용 불변과 읽기 시점 `stale` 표시.
- 프로젝트 접근 권한·민감도·실행/credential 권위·전역 관계 예산·멱등성·UNKNOWN 보존.
- Windows 정상 설치/실행·재부팅/복구 및 백업·격리 복원 검증.
- 기존 문서 형식과 URL 처리. 이미지 생성 관측은 별도 인가된 경로이며 미검증 관측으로 유지한다.

원래의 [VP 최종 인수](../vp-full-completion-2026-10-12/final-acceptance-2026-10-19.md)와
[기계 판독 증거](../vp-full-completion-2026-10-12/final-acceptance-evidence-2026-10-19.json)를 재사용한다.
새 모델 호출·과거 결과 재채점·새로운 품질 인증을 수행하지 않는다.

## 변경·호환성·운영 영향

- root `package.json`과 lockfile의 Application Version만 `0.1.0` → `1.0.0`으로 맞춘다.
- 독립 Module/Workspace Package와 Contract의 버전은 유지한다. 모든 `0.1.0`을 제품 버전으로 간주해 일괄 치환하지 않는다.
- dependency version·resolved URL·integrity·workspace dependency 범위·lockfile 해석 버전은 변경하지 않는다. OSS 추가/교체와 새 runtime 채택은 없다.
- 제품 로직·v6/0.9 gate·schema·credential·정책·데이터·보안 권위는 그대로다. 운영 migration과 앱 재시작은 수행하지 않는다.
- schema 기준은 기존 migration 140이며 이 버전 명명 변경은 migration을 추가하지 않는다.
- 일반 앱의 v11·SSC·신규 모델·negative 정책 활성화, audio/video 지원 및 후속 아키텍처 연구를 승인하지 않는다.
- `private: true`는 npm의 실수 발행 방지 설정으로 유지한다. GitHub 저장소가 비공개라는 뜻은 아니다.

## 알려진 제한

- 인증 Gold 기반 모집단 Precision/Recall·Calibration, 모든 자료에 대한 의미 정확도는 미인증/N/A다. 실제 여정 PASS를 인간 검증이나 전체 정확도 보장으로 확대하지 않는다.
- 복잡한 PDF 수식/글리프 fidelity와 inline PDF preview에 한계가 있다.
- 이미지 생성 설명은 원문 Evidence 또는 Fact가 아니다. 분석 경로는 격리 인수로 검증했으며 별도 승인 전 일반 운영 OFF를 유지한다. 이미지 실사용에는 승인된 Provider·정책 구성이 필요하다. 오디오·영상의 일반 제품 지원은 DEFER다.
- Windows 소스 설치·바로가기 실행을 검증했으며 범용 installer, 다른 OS의 동등한 제품 인수, 공개 다중 사용자 서비스를 새로 보장하지 않는다.
- 최초 실제 인수 7회에 대한 건별 실제 청구액·엄밀 adapter latency는 N/A다. 기존 비용 대조는 원래 검증 범위로만 재사용한다.
- 이후 사용자 승인에 따라 로컬 실험·개발 원시 자료는 영구 정리됐다. 과거 문서의 로컬 보존 위치는 당시 기록이며, 현재 근거는 Git에 남은 증거 요약·digest와 CI 기록이다. 로컬 raw packet의 현재 존재나 전체 실험 재현 가능성을 새로 주장하지 않는다.

## 검증·배포·복구

이 변경의 검증은 문서 링크/ADR/Canonical·완료 불변식, Markdown/JSON 포맷,
Application/lockfile 버전 일치, 의존성 불변과 diff 범위를 확인한다. 새 생산 구현이
없으므로 과거 실AI 여정을 다시 실행하지 않는다. 게시 후 exact-head와 main CI는
각각 별도로 확인하며 현재 로컬 PASS를 원격 CI PASS로 기록하지 않는다.

기존 설치의 운영 자료·Vault·journal·최신 백업은 보존한다. 버전 명명에는 DB 복원이나
초기화가 필요하지 않다. 후속 배포는 기존 정상 launcher/승인 경계를 따른다.
Rollback은 문서·Application Version 변경을 검토된 후속 커밋으로 되돌리는 것이며,
원장/SourceVersion/답변 기록을 삭제하거나 과거 `v1.0` 태그를 덮어쓰는 방식이 아니다.
