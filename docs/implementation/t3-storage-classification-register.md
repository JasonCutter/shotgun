# T3 Project Source 지식 저장소 분류표

> - 상태: **DESIGN FREEZE — 구현 전 기준**
> - DB 표본: `shotgun_test`, migration 001~077, 2026-09-23
> - 범위: 190 application base table / 29 schema
> - 권위: [ADR-171](../architecture/adr/ADR-171-t3-project-source-knowledge-reset.md)

이 표는 SQL `information_schema.tables`의 전체 190개 base table 목록을 schema별로 묶은 것이다. 구현은 같은 목록을 fresh DB에서 다시 추출해 **새 테이블·누락 테이블이 있으면 Preview와 CI를 실패**시킨다. “프로젝트 전체”라는 이름만으로 보존 대상의 데이터를 지우지 않는다. JSON/파일/캐시도 아래 별도 규칙을 적용한다.

동일 schema에서 JSON/JSONB/bytea **165개 컬럼(108개 테이블)**을 추출한 정확한 목록은 [T3 content-column inventory](./t3-content-column-inventory.tsv)에 있다. 각 컬럼은 이 표의 row 분류를 상속한다. C 또는 R인 row는 owner가 payload 내부 Source ID·원문·인용·프롬프트 필드의 판정과 scrub 결과를 증명한다. 새 컬럼이나 schema drift는 분류 전까지 U로 취급한다.

기호: **P** 보존, **D** Source-derived content 삭제, **R** payload scrub 후 최소 identity 유지, **B** 재구성, **S** 다른 참조 확인 후 CAS GC, **C** Source lineage 조건부, **U** 판정 불가 시 실행 차단.

## 추가 저장 영역

| 영역                                               | 판정                                                                                                                                       |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `.data/assets` 원본 CAS 및 `.gc/quarantine`        | S. 전역 OriginalAsset과 staging lease 재조회. quarantine 중은 별도 PENDING; positive safety period 후 sweep만 물리 완료.                   |
| Shotgun 관리 backup 디렉터리와 manifest            | old epoch backup을 재사용 불가로 표시하고 retention 정책에 따라 폐기·교체. restore는 외부 erasure journal보다 오래된 epoch를 거부.         |
| 클라이언트 draft/local cache 및 검색 캐시          | 새 knowledge epoch로 무효화·삭제. 오프라인 탭은 재연결 시 old epoch 데이터를 서버에 업로드하지 못함.                                       |
| Export 파일, launcher/runtime 로그, 작업 임시 파일 | Shotgun이 관리하는 경로를 inventory하고 Source content가 있으면 D/R. 독립 사용자가 복사한 외부 파일은 통제 범위 밖이라고 명시.             |
| 외부 AI 공급자와 외부 Action 결과                  | Shotgun DB 정리만으로 삭제되었다고 주장하지 않음. 공급자 보존 정책·외부 보상/삭제 절차가 필요하면 Preview blocker 또는 완료 제한으로 표시. |

## 구현 검증 규칙

1. 마이그레이션 전 fresh DB의 `information_schema.tables`와 이 목록, JSON/JSONB/bytea 컬럼과 별도 inventory의 **정렬된 완전 일치**를 검사한다. 새 테이블/컬럼은 설계 분류 없이는 CI 실패.
2. 각 보존 schema는 Project/Auth/AI/Settings fingerprint를 reset 전후 비교한다. `settings.resource_settings` 등 Source-scoped 예외만 명시적 처리.
3. JSON, text, bytea, 파일에는 테스트 canary를 넣어 Source→Evidence→Ask→Canonical→History의 모든 저장 복사본을 검출한다. 단순 행 수 0으로 완료 판정하지 않는다.
4. 각 owner의 `P/D/R/B/S/C/U` 선택은 SQL 직접 접근이 아닌 owner Port의 readback으로 확인한다. source 없는 독립 fixture를 함께 두어 과잉 삭제를 탐지한다.
5. 현재 스키마 기준 미분류·출처 불명·실행된 외부 Action 의존은 `U`이며 reset Preview를 차단한다. 운영 데이터에 `U`가 없다는 증거 없이 apply를 활성화하지 않는다.
