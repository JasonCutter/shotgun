## 1. 최상위 지시

**Shotgun VP 전체를 완성하라.**

이 요청은 계획서만 작성하라는 지시가 아니다.

현재 Canonical과 코드·미완료 목록을 확인하여 하나의 실행계획을 수립하고, 계획 수립 즉시 구현을 시작한다.

구현 도중 각 작업 패키지나 Section마다 사용자 승인을 요청하거나 다음 작업을 기다리지 않는다.

### 실행 원칙

1. 현재 미완료 기능의 전체 구현을 우선한다.
2. 실제 사용 가능한 End-to-End 제품 흐름을 먼저 완성한다.
3. 구현과 함께 기본 안전·계약 검증을 유지한다.
4. 전체 구현이 연결된 뒤 통합 검증을 실시한다.
5. 통합 검증에서 발견한 결함은 원인 분석 후 수정한다.
6. 수정 뒤 회귀 테스트를 수행하고 실패가 있으면 다시 수정한다.
7. 해당 완료 조건을 통과하면 다음 작업으로 자동 진행한다.
8. 사용자에게 기술적 선택이나 개별 결과 검토를 요구하지 않는다.
9. 완료했다고 판단하는 시점까지 가능한 모든 작업을 연속 수행한다.
10. 필수 증거가 확보되지 않은 항목은 완료로 위장하지 않는다.

**구현 → 통합 → 검증 → 보정 → 재검증 → 최종 인수**를 하나의 연속 작업으로 취급한다.

작업 도중 새로운 기술적 문제가 발견되면 기존 요청서의 세부 구현 방법에 얽매이지 말고 더 적절한 해결 방안을 조사·선택해 적용한다.

단, Canonical 권위·보안·원장·출처 무결성과 같은 핵심 계약은 유지한다.

## 2. 절대 변경하지 않을 제품 목표

Shotgun 사용자는 기본적으로 다음 두 동작만 수행한다.

**첫째, 자료를 투입한다.**

**둘째, 자료에 관하여 질문한다.**

나머지 지식 처리 과정은 Shotgun이 자동으로 수행한다.

사용자에게 다음을 요구하지 않는다.

- 프로젝트 생성·선택
- Source 수동 선택
- 개별 Claim·Fact·Relation 검토
- 지식 후보 승인
- 모델이 생성한 정답 검증
- 개별 AI 결과 수정 승인
- 실패한 내부 작업의 수동 재시도

일반 지식 흐름은 사용자 개입 없이 자동 처리한다.

단, 외부 시스템에 실제 변경을 수행하는 위험 Action과 시스템 운영 관리 권한은 기존 별도 보안 계약을 적용한다.

### 유지해야 하는 지식 원칙

- VP Knowledge Ledger가 활성 지식의 단일 기록 권위다.
- Claim과 객관적 Fact를 구분한다.
- 원본·SourceVersion·EvidenceSpan은 보존한다.
- AI 출력만으로 객관적 사실을 인증하지 않는다.
- 충돌하는 주장은 출처·조건·시점과 함께 보존한다.
- 최신 지식과 과거 답변을 구분한다.
- 불확실한 결과는 명시적으로 기록한다.
- Compiled Truth 및 검색 Projection은 재생성 가능한 파생 상태다.
- 사용자별 접근·민감도와 AI 제공자 전송 정책을 지킨다.
- AI 결과의 무단 외부 실행과 근거 없는 Canonical 승격을 금지한다.

## 4. 전체 구현 작업 순서

다음은 권장 순서다. 상위 에이전트는 의존성과 실제 병목에 따라 작업을 병렬화하거나 순서를 최적화할 수 있다.

### Phase 1 — 평가 기반과 VP-05 완성

기존 A1·A2 계약은 유지한다.

A3부터 남은 평가 계약을 상위 에이전트가 구체화하고 구현에 필요한 범위를 확정한다.

필수 작업:

- 관계 종류·방향·근거·복수 허용 해석 계약
- 현재 v6의 6종과 보존된 v11의 7종 의미 정책 구분
- Raw 판단과 실제 채택 결과의 분리
- Precision, Recall, F1, 중요 오류, 안정성의 분자·분모
- abstention, invalid output, runtime failure 구분
- 분모 0의 N/A 처리
- 대표 사례와 제품 질문의 대응
- 검증된 외부 reference provenance 확보 방안
- 후보 관계 축소 recall 검증
- 실제 호출 수·토큰·p50/p95·청구 비용 대사
- 예산·재시도·임계값의 타당성 확인

**중요:** 기존 72쌍·432회·B v1 12회는 역사적 개발 증거다. 새로운 Gold 또는 인증 의미 정확도로 자동 승격하지 않는다.

외부 독립 의미 검증 증거를 확보하지 못하면 그 부분은 UNVERIFIED로 기록한다. 사용자가 개별 정답을 검토해야 한다는 조건을 만들지 않는다.

평가 증거 확보가 지연되더라도 독립적인 다른 구현 작업은 계속 진행한다.

### Phase 2 — 실제 제품 End-to-End 완성

다음 시나리오를 설치 가능한 실제 제품에서 완성한다.

1. 빈 단일 Shotgun을 실행한다.
2. 사용자가 자료 A를 한 번 투입한다.
3. 자동 변환·원문 근거 추출·지식 기록이 완료된다.
4. 사용자가 질문하면 근거와 함께 답변한다.
5. 자료 B를 추가한다.
6. A와 B의 합의·차이·충돌·조건을 자동으로 구분한다.
7. 자료 A의 수정 버전을 투입한다.
8. 과거 버전은 현재 답변에서 제외한다.
9. 같은 질문을 다시 수행하면 최신 A와 B를 반영한다.
10. 처리가 완료되기 전에 질문했다면 같은 AnswerRun에서 기다렸다가 자동 재개한다.
11. 처리 실패·미해결·근거 부족·접근 불가 상황에서 잘못된 확정 답변을 만들지 않는다.
12. 전체 과정에서 사용자의 지식 검토·승인 동작은 0회여야 한다.

Frontend, Application, Worker, PostgreSQL, Evidence, Ledger, Ask 사이의 연결을 실제로 확인한다.

Fake Provider의 성공과 실제 DeepSeek 의미 품질을 구분한다.

실제 DeepSeek 검증은 격리 환경, 기존 인가된 자격 증명과 유효한 비용·egress 정책 안에서 필요한 최소 범위로 수행한다.

### Phase 3 — 남은 제품·자료·보안 구현

VP-03·04·08·09의 미완료 조건을 닫는다.

- 숫자·표·수식·조건·시간·부정 표현의 누락 및 왜곡 처리
- 형식별 지원 범위와 명확한 미지원 처리

- SourceVersion 갱신과 Answer Historical Freshness

이미 통과한 기능은 보존하고 실제 누락된 조건에만 변경을 적용한다.

## 5. 구현 완료 후 집중 보정

이번 작업의 우선순위는 작은 문제를 하나씩 해결하며 반복적으로 설계를 멈추는 것이 아니라, **전체 제품이 작동하는 상태까지 연결하는 것**이다.

진행 방식:

**1차 — 전체 구현**

누락된 기능과 연결 경로를 완성한다. 기능별 smoke test와 필수 안전 테스트는 수행하되, 미세한 품질 튜닝 때문에 독립적인 다음 작업 전체를 중지하지 않는다.

**2차 — 전체 통합 검증**

실제 제품 시나리오, 형식별 자료 처리, 장애·보안·비용·품질 조건을 종합적으로 검증한다.

**3차 — 결함 수정**

실패 항목을 P0/P1/P2로 분류한다. 원인과 영향을 추적해 최소 수정하고 관련 회귀 테스트를 추가한다.

**4차 — 최종 재검증**

실제 제품, 설치본, CI, 데이터 권위, 보안, 복구, 비용 및 문서 계약의 증거를 다시 확인한다.

같은 문제가 반복된다면 무제한 재시도나 prompt 변경 대신 설계와 가정을 재검토한다.

보완 작업 때문에 기존 기능이 퇴행하면 해당 수정은 완료 처리하지 않는다.

## 6. 상위 에이전트에게 위임하는 권한

상위 에이전트는 이번 VP 전체 구현 목표 안에서 다음을 자율적으로 수행한다.

- 상세 구현계획 작성 및 작업 순서 조정
- 기존 코드의 분석과 수정
- 필요한 하위 에이전트 작업 분배
- 외부 OSS·공식 문서·GitHub 사례 조사
- 적절한 기술과 구현 방식 선택
- 테스트 작성 및 격리 환경 검증
- 원인 분석·결함 수정·재검증
- 관련 ADR 초안과 구현 기록 작성
- 작은 범위의 독립 브랜치·커밋 구성
- 중간 작업 보고 및 완료 증거 취합

**매 단계마다 사용자 승인 요청서를 새로 작성하지 않는다.**

통상적인 비파괴적 개발·테스트와 그에 필요한 기술적 결정은 연속 수행한다.

GitHub 게시·병합은 기존 보호 브랜치 및 승인 정책을 따른다. 승인된 범위의 Draft PR과 CI 준비는 계속 진행하되, 별도 승인이 필요한 merge는 임의 승인으로 위장하지 않는다. Merge 대기 중에도 다른 독립 작업은 계속한다.

### 별도 권한이 필요한 예외

다음은 VP 전체 구현 지시만으로 무제한 허용하지 않는다.

- 실제 운영 DB 또는 원본 Asset의 파괴적 변경
- 비밀 키·계정·권한의 무단 변경
- 인가되지 않은 외부 AI 전송
- 기존 예산을 초과하는 실 API 호출
- 새로운 생산 지식 권위의 도입
- 중요한 Canonical·보안 계약의 변경
- 동결된 Gold-B-7의 개봉
- 기존 72/432/B12 원본 변경 또는 B 잔여 24회 자동 재개
- 실제 외부 Action의 무단 실행
- 검증되지 않은 release 또는 파괴적 cutover

이러한 사항이 필요하면 정확한 사유와 최소 승인 범위를 한 번에 정리한다.

해당 작업만 보류하고 다른 구현을 계속한다.

---

## 7. 작업 중단을 허용하지 않는 상황

다음 이유만으로 VP 전체 작업을 중단하거나 사용자에게 되돌리지 않는다.

- 하나의 테스트 실패
- 특정 하위 에이전트의 실패
- 설계 대안이 여러 개라는 이유
- 기존 구현이 불완전하다는 이유
- OSS 후보가 기대에 못 미친다는 이유
- 하나의 PR이 검토 대기 중이라는 이유
- 독립 품질 검증 자료가 아직 부족하다는 이유
- 후속 기능을 구현할 수 있는데 선행 기능의 비핵심 보정이 남았다는 이유

실패한 작업은 정확한 원인을 남기고 해결하거나, 독립 작업을 먼저 수행한 뒤 돌아온다.

### 실제 중단 조건

데이터 손실·권한 침범·비밀 유출·복구 불가능한 변경·무제한 비용 발생 가능성이 있는 작업은 안전하게 중지한다.

필수 외부 검증자·권한·자격 증명·청구 정보처럼 에이전트가 만들 수 없는 외부 의존성이 필요한 경우에도 그 항목의 완료를 허위 선언하지 않는다.

이 경우 남은 독립 작업을 수행하고 최종 미해결 조건으로 분리한다.

## 8. 완료 판정 기준

다음 두 상태를 분리한다.

### IMPLEMENTATION_COMPLETE

- 계획된 필수 구현 범위가 연결됐다.
- 실제 제품 경로가 실행 가능하다.
- 잔여 개발 결함과 미검증 항목이 분류됐다.
- 이후 통합 보정과 최종 검증을 진행할 수 있다.

이는 최종 VP COMPLETE가 아니다.

### VP_FINAL_ACCEPTANCE_COMPLETE

다음 조건을 만족할 때만 선언한다.

1. VP-03~11의 필수 미완료 조건이 해결됐다.
2. VP-0~VP-4의 제품·구조 계약을 충족한다.
3. Module·Flow·Product·Architecture·OSS Integration Gate가 통과됐다.
4. 실제 제품에서 자료 투입과 질문의 End-to-End 인수가 통과됐다.
5. 원문·버전·권한·불확실성·충돌·증분 처리 계약이 통과됐다.
6. 승인된 평가 기준에 따라 필요한 의미 품질 증거를 확보했다.
7. 장애 복구와 중복 방지, Rollback 조건이 통과됐다.
8. 비용·실제 청구·예산 조건이 검증됐다.
9. 설치본과 검증된 Canonical main의 실행 identity가 일치한다.
10. 사용자에게 지식 검토·승인 작업이 추가되지 않는다.
11. 승인된 코드·문서·증거가 Git Canonical에 반영됐다.
12. 필수 blocker가 없다.

기준에 미달하는 항목을 `COMPLETE_WITH_LIMITS`로 우회하지 않는다. 해당 상태는 기존 Definition of Done의 허용 조건이 충족될 때만 사용한다.

## 9. 진행 기록과 인계

전체 작업을 하나의 Master Execution Plan으로 관리한다.

기존 `VP-01`~`VP-11` ID는 변경하지 않는다.

각 항목에 다음을 기록한다.

- 기존 구현 상태
- 재사용한 통과 증거
- 새로 구현한 범위
- 누락·실패 원인
- 변경 파일과 커밋
- 테스트 결과
- 남은 blocker
- 다음 의존 작업
- Architecture/ADR 영향
- 완료 판정

중요한 변경은 이유, 제외 대안, 영향 및 되돌리기 방법을 기록한다.

과거 결정을 조용히 수정하거나 실패 기록을 삭제하지 않는다.

작업을 다른 세션·하위 에이전트로 인계할 때는 마지막 검증된 commit, 남은 작업, 보호 자료, 다음 실행 명령을 포함한 checkpoint를 남긴다.

중간 보고는 완료된 범위와 blocker를 알리기 위한 것이며, 별도 승인이 필요하지 않은 작업을 멈추는 신호로 사용하지 않는다.

## 10. 최종 산출물

작업이 끝나면 다음을 제출한다.

1. VP 전체 구현 및 최종 인수 보고서
2. VP-01~11 완료 현황 및 Gate별 증거
3. 실제 제품 End-to-End 검증 결과
4. AI 의미 품질·미검증 범위·비용·지연 보고
5. 장애·복구·백업·Rollback 검증 결과
6. 보안·인가·프롬프트 인젝션 검증 결과
7. OSS Integration Decision 및 ADR 변경 이력
8. GitHub PR·merge SHA·post-merge CI 결과
9. 최종 설치본의 실행 identity
10. 남은 Known Limitations 및 미해결 외부 의존성

**최종 지시**

계획 수립 자체를 별도 승인 Gate로 만들지 말 것.

사용자에게 개별 기술 판단이나 지식 검토를 요구하지 말 것.

기존의 구현과 통과 증거를 최대한 재사용할 것.

독립적으로 수행 가능한 작업이 남아 있는 동안 전체 작업을 중지하지 말 것.

먼저 전체 구현을 연결하고, 통합 검증으로 발견한 결함을 수정하여 최종 인수 기준을 충족시킬 것.

**목표는 보고서 작성이 아니라 실제 사용 가능한 Shotgun VP 전체 완성이다.**
