# VP-11 — 최종 설치본 실모델 여정의 최소 종료 절차

**PREPARED / NOT_AUTHORIZED_FOR_EXECUTION / NOT_RUN.** 2026-10-18.

## 필요한 이유와 재사용

[tracker의 VP-11](../vp-completion-tracker.md)은 최종 main의 설치 아이콘에서 빈
공간부터 자료 투입·실제 AI 질문·수정본 반영을 다시 확인하도록 명시한다.
현재 확보된 같은 main의 설치/Fake 전체 여정, 과거 격리 실모델 전체 여정,
운영 설치본의 기존 자료 실모델 질문은 각각 보존한다. 이를 단일한 최신 설치본
실모델 여정으로 합쳐 보고하지 않는다. 인증 Gold 확보나 새 모델 비교가 목적이 아니다.

기존 Windows Canonical 설치·normal owner launcher·격리 A/B/수정본 시나리오와
격리 실모델 실행/호출 원장/egress/예산 검증 도구를 재사용한다. 새 서비스,
일반 운영 프레임워크, 모델·정책·schema·parser 또는 새 정답 권위를 만들지 않는다.
자료는 외부 전송 가능한 짧은 합성 문장으로 고정하고 실제 사용자 자료를 복제하지 않는다.

## 실행 전 조건

1. 이번 최소 보정과 종료 문서를 별도 승인으로 Canonical에 게시하고, 승인된
   exact head의 필수 CI와 설치 source/tree identity를 고정한다. 운영 설치본을
   새 head로 교체하는 작업은 이 로컬 문서 승인에 포함하지 않는다.
2. 승인된 Windows 설치·아이콘 경로와 **빈 격리 제품 DB·별도 asset root**를
   바인딩한다. 기존 운영 DB·asset·앱 runtime identity/port·설정·Vault와 충돌하거나
   임의로 전환하는 경로는 거부한다. 기존 운영 앱의 정지/재시작이 필요하면 그
   영향까지 별도 실행 승인에 포함하며 조용히 정지하지 않는다.
3. 실 credential의 재사용·격리 실행 주체/프로젝트·egress 범위는 기존 인가
   경로로 확인한다. 준비 단계에서 credential을 복호화·복제·설정하지 않는다.
4. **동일한 실제 글로벌 authority**가 보고하는 UTC 날짜·store·authority·fingerprint,
   기본 일일 한도100·claimed count·reservation/UNKNOWN을 확인한다. 격리 제품
   실행이 운영 제품 DB에 연결되거나 workload-local 예산으로 우회하면 STOP한다.
5. 2026-10-18의941회는 이미 소비된 이력이다. CLOSED인841건 한시 허용을
   재개·수정·재사용하지 않는다. 이후 새 UTC일의 권위상 충분한 잔량을 확인하고,
   이 여정의 **실 HTTP 호출 총10회 이내** 상한을 별도 승인·실행 증거로 고정한다.
   10회는 품질을 보장하는 목표량이 아니라 최대치다. 관계 호출은 기존 전역
   카운터에도 그대로 계상하고, 추출/Ask를 포함한 전체 호출 상한도 별도로 지킨다.

## 최소 여정과 판정

| 순서 | 사용자 동작과 검증                                                                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 빈 격리 지식 공간을 승인된 설치 아이콘으로 실행한다. 실제 owner/child/port·main tree·DB/asset·정책 identity를 확인한다.                                             |
| 2    | 합성 자료 A v1의 수량42를 투입하고 질문한다. 실제 응답42와 A v1의 정확한 Evidence/인용을 확인한다.                                                                  |
| 3    | 같은 대상의 수량43을 진술하는 B를 추가하고 같은 질문을 한다. 두 근거와 차이를 보존하며 AI가 임의로 한 값을 객관적 사실로 확정하지 않는지 확인한다.                  |
| 4    | A를44인 v2로 수정하고 재질문한다. 현재 A v2/B를 인용하고42를 현재 값으로 인용하지 않는지 확인한다. 과거 A v1 답변은 원문·citation을 유지하고 stale 표시를 확인한다. |
| 5    | 현재 SourceVersion·Evidence·decision receipt·claim/attempt/response·관계 보류·원장 재생을 대조한다. 기존 설치/재부팅/복구·권한·지원 형식 증거는 재사용한다.         |

관계가 보류돼도 원문 질문은 가능해야 한다. 기대 관계 라벨·confidence를 얻기 위해
재호출하거나 판단 보류를 미처리로 바꾸지 않는다. A/B/수정본의 추출3회·질문3회와
필요한 관계 처리만 수행하며 남은 호출을 소진하지 않는다. 실제 호출 수는 원장에서
관측해 보고하며 계획량을 실제량으로 쓰지 않는다.

## STOP과 종료

실행 identity/권한/정책/SourceVersion drift, 예상 밖 실행자, 상한 초과 가능성,
UNKNOWN·불확실한 commit·readback 실패, 인용/최신성/접근 실패가 있으면 STOP한다.
상한에 도달한 미완료 여정을 PASS로 표시하거나 자동 재시도·prompt/parser 수정으로
그 자리에서 복구하지 않는다. 승인받은 소유 격리 프로세스만 종료하고 이력과
응답·토큰·미결 상태를 보존한다. 운영 원본에는 테스트 결과를 이관하지 않는다.

통과 후 실제 실행·설치·원장·지원/제외 범위와 인증 N/A를 묶은 최종 보고를
Canonical에 반영하는 승인 절차를 밟는다. 이 문서만으로
`VP_FINAL_ACCEPTANCE_COMPLETE` 또는 추가 실호출 승인을 부여하지 않는다.
