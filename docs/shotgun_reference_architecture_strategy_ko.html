1. 최종 전략 요약

shotgun은 네 프로젝트를 병렬 실행하거나 단순 조립하는 제품이 아니다. 검증된 우수 기술만 추출하고, canonical 지식·근거·승인·충돌·감사 권한을 shotgun이 통제하는 독립 시스템이다.

CORE ENGINE

garrytan/gbrain

Page·Fact·Graph·Timeline·Search·MCP·Minion Job·Dream Cycle·migration·복구를 담당한다.

SELECTED SOURCE & VALIDATION PARTS

lucasastorian/llmwiki

HTML/XLSX 변환, Highlight/Annotation, Lint, Watcher event, Reconcile 패턴을 선별한다.

PRODUCT WORKFLOW REFERENCE

ddsyasas/llm-wiki

Source intake, Ask/Chat, 비용·모델·설정, 액션 중심 홈의 UX 패턴을 활용한다.

EDITOR & HUMAN COCKPIT TECHNOLOGY

Inkeep OpenKnowledge

Visual/Source 편집 UX, 2D Graph, Agent Activity, Burst Diff, Entity Vault 템플릿을 반영한다.

최종 제품 전략
새 shotgun-web과 typed shotgun API를 유지한다. 네 레퍼런스의 전체 런타임을 중첩하지 않고, 각 프로젝트에서 검증된 모듈·UX·운영 원칙만 shotgun 경계 안으로 가져온다.

ddsyasas 기반 UI, 별도 2D 그래프 추후 설계, 단순 Markdown 편집기, 신규 Job/Audit UI 자체 설계

3. 4개 레퍼런스의 최종 역할

3.1 garrytan/gbrain — 두뇌와 중추 실행 엔진

담당

  • 영구 Page·Fact 저장과 Facts fence
  • Alias·Canonicalization·Timeline·Relation Graph
  • Search·Think·Citation·Gap
  • MCP operation contract
  • Minion Job Queue·retry·timeout·lock recovery
  • Dream Cycle·PGLite/PostgreSQL·migration

채택 원칙

gbrain은 참고 구현이 아니라 실제 기반 엔진이다. shotgun은 외곽 package·migration·operation·adapter를 추가하고 upstream core patch를 최소화한다.

3.2 lucasastorian/llmwiki — 선별된 수집·변환·검증 부품 공급원

등급부품shotgun 적용
BHTML cleaner, XLSX extractor독립 converter package와 SourceRecord·EvidenceSpan 출력 계약으로 연결
BHighlight·Annotation원문·사용자 메모·LLM Fact의 provenance 분리
BDeterministic LintVaultFS 의존을 제거하고 gbrain/shotgun adapter에 연결
BWatcher·ReconcileSource event producer와 converter staging recovery로 축소
CEvidence·Citation·Stale테스트만 참고하고 stable ID·gbrain Graph 기반으로 재구현
DVaultFS 전체·SQLite·FTS·MCP·UI제품 런타임에서 제외

3.3 ddsyasas/llm-wiki — Source·Ask·비용 중심 제품 워크플로 참고

ddsyasas의 전체 Next.js 앱을 유지하지 않는다. UI가 기존 SQLite·파일시스템·ingest/query/lint에 강하게 결합되어 있으므로, 상호작용 모델과 제한된 presentation component만 새 shotgun 화면에 반영한다.

반영할 강점

  • 액션 중심 Home
  • Paste/File/URL Source intake
  • 비용 사전 확인과 모델 선택 UX
  • Ask·Chat composer와 결과 레이아웃
  • 설정·비용·Command palette 패턴

제외할 부분

  • SQLite·Markdown 폴더 영구 저장
  • 기존 ingest/query/lint core와 LLM client
  • 임의 절대경로 기반 multi-wiki 관리
  • 단일 blocking request와 비복구형 progress
  • 3D canvas-only Graph

3.4 Inkeep OpenKnowledge — 편집기·2D Graph·Human/Agent Activity 기술 공급원

채택·반영

  • Visual/Source mode UX와 Markdown 보존 원칙
  • 2D Graph interaction·label·neighborhood UX
  • Agent Activity와 changed-file grouping
  • Burst Diff를 활용한 변경 검토
  • Entity Vault 폴더·템플릿·Compiled Truth/Timeline 표현
  • 선택적 Draft CRDT 가능성

채택하지 않는 것

  • OpenKnowledge 전체 runtime과 local filesystem API
  • Markdown/Yjs를 shotgun canonical system of record로 승격
  • 즉시 collaborative mutation을 canonical write로 사용
  • OpenKnowledge MCP·검색·Git sharing을 병렬 엔진으로 유지
  • TiptapEditor 전체를 무리하게 직접 추출
중요한 역할 구분
OpenKnowledge는 shotgun의 두뇌가 아니다. 검증으로 우수성이 확인된 사람의 검토·편집·관계 탐색 경험을 shotgun의 canonical·승인 경계 뒤에 제공한다.

네 프로젝트를 결합할 때 가장 중요한 원칙은 어느 시스템이 최종 진실을 기록할 권한을 갖는가를 하나로 고정하는 것이다.

OpenKnowledge Markdown/Yjs, ddsyasas Markdown, gbrain DB가 각각 독립적인 최종 진실로 쓰이는 구조를 만들지 않는다. Markdown은 사람이 검토하는 projection 또는 staged 입력이며, canonical 전환은 shotgun Changeset과 Approval이 통제한다.

Canonical write 규칙

  → Draft ChangeSet
  → validation + evidence check + impact preview
  → awaiting_approval
  → approve
  → canonical Fact / Claim update
  → Compiled Truth projection
  → Markdown / Graph / Search refresh
  → HistoryEvent

8. shotgun 고유 도메인과 Typed API

Project

사용자 workspace와 gbrain namespace를 연결한다. 로컬 경로 자체는 identity가 아니다.

Source / SourceVersion

path와 독립적인 stable ID, hash, parser, path history, 상태를 관리한다.

EvidenceSpan

page·section·offset·table cell·image bounding box까지 정확히 지정한다.

Fact / Citation

Claim과 EvidenceSpan을 stable ID와 source version으로 연결한다.

Directive

사용자의 수정·금지·우선순위를 증거와 분리된 권위 record로 관리한다.

Conflict

경쟁 Fact를 삭제하지 않고 unresolved/resolved/manual_review 상태로 보존한다.

Changeset / Approval

Fact·Page·Conflict·Gap·비용·impact를 하나의 승인 단위로 묶는다.

Compiled Truth

활성 Fact·Directive·Conflict·시간 유효성을 반영한 현재 읽기 모델이다.

Job / JobEvent

작업 상태·진행·재시도·resume·비용과 Activity 표시를 연결한다.

HistoryEvent / Revision

누가 무엇을 왜 변경했는지 추적하고 rollback proposal을 만든다.

반드시 유지할 원칙

  • typed API가 UI와 engine 사이의 유일한 제품 경계다.
  • 모든 mutation은 project scope, authorization, idempotency, audit를 가진다.
  • Source·Evidence·Fact·Directive·Conflict·Draft는 서로 다른 resource다.
  • 승인·rollback은 Changeset을 통해 수행한다.
  • OpenKnowledge식 편집·Activity는 관찰·Draft UX이며 canonical 권한이 아니다.
  • Graph UI가 이해하지 못하는 relation·confidence도 adapter에서 버리지 않는다.

14. 성공 조건

영역필수 성공 조건
Sourcerename·move 후 동일 source_id와 version history가 유지되고 원본 byte가 변하지 않는다.
Evidence모든 핵심 Fact에서 정확한 source version·page·offset·table/image 위치로 역추적한다.
Citation동명 파일을 임의 선택하지 않고 Source ID와 EvidenceSpan을 사용한다.
Jobsrefresh·disconnect 후 진행 상태를 복원하고 retry/cancel/idempotency가 동작한다.
Approval승인 모드에서 durable canonical write가 Changeset 승인 전에 발생하지 않는다.
Directive사용자 수정이 이후 자동 처리에 의해 사라지지 않고 revocation과 audit가 가능하다.
Conflict경쟁 Fact를 삭제하지 않고 unresolved/resolved 상태와 근거를 보존한다.
ImpactSource 변경이 관련 Fact·Truth·Cache에 재귀 전파되고 무관한 노드는 제외된다.
EditorVisual/Source no-op 전환에서 의미 손실이 없고 지원하지 않는 문법을 조용히 삭제하지 않는다.
Activityactor·Job·변경 파일·Diff·승인 상태가 실제 backend 상태와 일치한다.
Graphrelation·confidence를 보존하고 2D canvas 외에 키보드 가능한 목록 대안을 제공한다.
CRDT동시 편집이 수렴하며 canonical 승인 경계를 우회하지 않는다.
UI사용자가 내부 DB를 몰라도 Add Source, Ask, Browse, Correct, Review, Rollback을 수행한다.
SecurityURL private-network 차단, redirect 재검사, workspace confinement, project authorization을 적용한다.
비중복영구 DB·검색·Graph engine·Job·LLM 실행 권한이 명확히 일원화된다.

15. 최종 정의

shotgun은 gbrain, lucas, ddsyasas, OpenKnowledge를 설치해 함께 실행하는 묶음이 아니다. gbrain을 핵심 엔진으로 사용하고, 세 레퍼런스의 검증된 기술을 shotgun-owned canonical·policy·approval 경계 안에서 재구성한 독립 제품이다. 

shotgun
=
gbrain Core Engine
+
selected lucas modules
  (HTML/XLSX + Highlight + Lint + Watcher + Reconcile)
+
selected ddsyasas workflow patterns
  (Source Intake + Ask/Chat + Cost + Settings + Action Home)
+
selected OpenKnowledge technologies
  (Visual/Source UX + 2D Graph + Agent Activity + Burst Diff
   + Entity Vault Template + Optional Draft CRDT)
+
shotgun-owned domain and product
  (Canonical Fact/Claim + Stable Source Identity + EvidenceSpan
   + Citation + Recursive Impact + Directive + Priority + Conflict
   + Changeset + Approval + Compiled Truth + Job + Audit
   + Typed API + New Web UI)
gbrain

두뇌와 중추 실행 엔진

lucas

선별된 수집·변환·검증 부품

ddsyasas

Source·Ask·비용 중심 제품 워크플로 참고

OpenKnowledge

편집기·2D Graph·Activity·Diff 기술 공급원

shotgun

canonical 지식, 근거, 사용자 권위, 승인, 충돌, 감사와 제품 경험을 하나로 통제하는 독립 시스템
