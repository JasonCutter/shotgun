Shotgun 프로젝트 구조 및 연결 프로세스 분석 보고서

Hexagonal Modular Monorepo Architecture 및 지식 처리 파이프라인 명세

1. 프로젝트 개요 & 아키텍처 원칙

🎯 Shotgun 핵심 개념 PKS

Shotgun은 단일 지식 원본에서 시작하여 탄환처럼 여러 방향으로 확산되는 개인 지식 시스템(Personal Knowledge System)입니다. 원본 접수부터 Fact/Claim 추출, 정사 지식(Canonical Knowledge) 저장, 지식 그래프 형성, 안전한 외부 실행까지 처리합니다.

🏗️ Monorepo 구조 npm workspaces

독립적인 레이어로 분리된 npm workspace 구조를 가집니다. 최상위 package.json을 중심으로 apps, assemblies, modules, packages, adapters로 명확히 역할이 구분됩니다.

🔌 Port & Adapter 패턴 Clean Architecture

비즈니스 도메인(modules)은 순수 TS 인터페이스(Port)만 정의하며, 외부 기술(Postgres DB, Gemini AI, Lucas Text Locator 등)은 adapters에 격리되어 손쉬운 교체 및 Contract 테스팅을 지원합니다.

AGENTS.md Rule Policy AI Agent 작업 수칙, 도메인 소유권 경계, OSS 평가 및 통합 규정, Definition of Done 지정

assemblies/shotgun-app/src/main.ts Assembly 백엔드 실 구동 엔트리포인트. Env 로드, DB Pool/AI Client 인스턴스화, 어댑터 의존성 주입(DI) 및 서버 시작

packages/kernel/ Package Shotgun 핵심 커널. ShotgunKernel, Command/Query 디스패처, 이벤트 버스, 도메인 기초 공통 타입 정의
packages/contracts/ Package 모듈 간 격리된 통신을 위한 DTO, 데이터 스키마 및 이벤트 계약(Contract) 명세
packages/authentication/ Package 사용자 인증, 비밀번호 해싱, 보안 컨텍스트 검증 및 세션 권한 관리
packages/policy/ Package 외부 시스템 Action 실행 시 위험도 평가 및 보안 정책 엔진
packages/connector-runtime/ Package 외부 연동 액션 커넥터 실행 및 결과 감사(Audit Log) 수집 런타임
packages/lucas-text-locator/ Package 원본 문서 내 텍스트 오프셋/라인/문자 단위 오프셋 탐색 보조 라이브러리
modules/intake/ Module 외부 지식 원본 소스(웹페이지, 파일, 텍스트) 수집 접수 및 메타데이터 관리
modules/original-asset/ Module 수집된 원본 파일의 바이너리/스트림 저장 및 물리적 Asset 참조 관리
modules/transformation/ Module PDF, HTML, XLSX 등 다변화된 원본 문서를 정규 텍스트 및 세그먼트로 표준 변환
modules/evidence/ Module 변환된 텍스트와 원본 Asset 간의 정밀 위치 근거(Evidence Span: Line/Char Range) 추적 매핑
modules/candidate-generation/ Module LLM 및 규칙 엔진을 활용하여 변환 텍스트에서 Fact/Claim 지식 후보 파싱 생성
modules/validation/ Module 추출된 지식 후보의 구조적 타당성, 무결성 및 근거 Span 연결성 검증
modules/comparison/ Module 신규 검증 후보와 기존 정사 지식(Canonical Knowledge) 간의 차이(Diff) 분석 및 충돌 감지
modules/change-set-review/ Module 사용자의 검토 및 승인을 기다리는 변경집합(Draft ChangeSet) 상태 관리
modules/canonical-knowledge/ Module 승인된 ChangeSet을 불변의 정사 지식(Commit History & Snapshot)으로 스토어 저장
modules/knowledge-model/ Module 정사 지식 간 상호 연결 관계(Knowledge Graph) 구성 및 변경 영향도(Impact) 계산
modules/compiled-truth/ Module 지식 그래프와 정사 지식을 통합하여 최종 신뢰할 수 있는 Compiled Truth View 뷰 프로젝션
modules/projection-search/ Module Compiled Truth 및 베인 지식 대상 전문 검색(FTS), 필터링, 벡터 탐색 서비스 제공
modules/cited-answer/ Module 검색 결과와 Evidence Span을 결합하여 명확한 출처 인용이 명시된 QA 답안 생성
modules/action-execution/ Module 검증된 지식을 기반으로 외부 서비스(Slack, GitHub 등) Action 제어 및 실행 기록 관리
adapters/postgres/ Adapter Stage 2 수집/원본 자산 저장을 위한 PostgreSQL 데이터베이스 연동 구현체
adapters/ai-provider-gemini/ Adapter Google Gemini API 연결 및 LLM 프롬프트/응답 파싱 어댑터 (@google/genai)
adapters/plain-text-lucas-augmented/ Adapter lucas 레퍼런스 기반 강화 텍스트 탐색 및 Evidence 위치 지정 어댑터
adapters/document-format-python/ Adapter Python 파이프라인 연동 기반 문단/문서 포맷 변환 어댑터
adapters/text-diff-jsdiff/ Adapter JSDiff 라이브러리를 활용한 텍스트 및 지식 변경점 차이 분석 어댑터
adapters/networkx-impact-oracle/ Adapter 지식 변경 시 연관된 다른 지식에 미치는 영향(Impact Analysis) 추적 어댑터
scripts/ Scripts 품질 게이트(quality-gate.ts), OSS 검증(oss-gate.ts), DB 마이그레이션(database.ts) 등 관리 도구

3. 파일간 연결 고리 및 엔드투엔드 처리 프로세스

Shotgun의 지식 처리는 원본 데이터 입력부터 시작되어 8단계의 파이프라인을 거치며 검증 및 축적됩니다.

Step 01 원본 접수 및 자산 저장

연결 흐름: apps/shotgun-web ➔ assemblies/shotgun-app/src/server.ts ➔ modules/intake & modules/original-asset ➔ adapters/asset-storage-local / adapters/postgres

설명: 사용자가 웹 UI 또는 API를 통해 문서/링크를 제출하면, intake 모듈이 메타데이터를 수집하고 original-asset 모듈이 물리적 파일(바이너리)을 스토리지 어댑터에 안전하게 저장합니다.

Step 02 텍스트 변환 및 근거 추적

연결 흐름: modules/transformation ➔ adapters/document-format-python ➔ modules/evidence ➔ adapters/plain-text-lucas-augmented & packages/lucas-text-locator

설명: 저장된 원본 파일을 일반 텍스트로 표준화 변환한 뒤, 변환된 텍스트의 각 문장/단락이 원본 파일의 몇 번째 줄/문자에 해당하는지 EvidenceSpan을 형성하여 근거 위치를 고정합니다.

Step 03 AI 지식 후보 추출

연결 흐름: modules/candidate-generation ➔ modules/ai-provider ➔ adapters/ai-provider-gemini

설명: 텍스트 및 근거 정보를 ai-provider 모듈을 통해 Gemini API로 전달하여, 텍스트 내에서 의미 있는 Fact(사실) 및 Claim(주장) 지식 후보(Candidate)를 자동 추출합니다.

Step 04 후보 검증 및 차이(Diff) 분석

연결 흐름: modules/validation ➔ modules/comparison ➔ adapters/text-diff-jsdiff ➔ packages/kernel

설명: validation 모듈이 후보 지식의 스키마와 근거 매핑 정합성을 검증하고, comparison 모듈이 text-diff-jsdiff 어댑터를 사용해 기존 저장된 정사 지식과 새로 들어온 후보 지식 간 차이점(Diff)을 분석합니다.

Step 05 사용자 검토 & 정사 지식 커밋

연결 흐름: modules/change-set-review ➔ apps/shotgun-web (승인) ➔ modules/canonical-knowledge ➔ adapters/postgres-stage6

설명: 생성된 변경집합(Draft ChangeSet)이 사용자 UI 대시보드에 노출됩니다. 사용자가 승인하면 canonical-knowledge 모듈이 이를 불변의 정사 지식(Canonical Knowledge)으로 커밋 및 이력(Commit Log)에 기록합니다.

Step 06 지식 그래프 & 컴파일 뷰 생성

연결 흐름: modules/knowledge-model ➔ adapters/networkx-impact-oracle ➔ modules/compiled-truth ➔ adapters/postgres-stage10

설명: 정사 지식 간 연관 관계를 그래프(Knowledge Graph)로 구성하고, 지식 수정 시 미치는 영향을 계산한 후 최종적으로 빠르게 조회 가능한 CompiledTruthProjection 뷰로 컴파일합니다.

Step 07 검색 및 근거 인용 답변 (QA)

연결 흐름: modules/projection-search ➔ adapters/postgres-stage7 ➔ modules/cited-answer ➔ apps/shotgun-web

설명: 사용자의 질의에 대해 전문 검색(FTS) 및 벡터 탐색을 수행하고, 찾아낸 지식과 이에 연결된 원본 근거(Evidence Span)를 바탕으로 신뢰성 높은 출처 인용 답변을 생성합니다.

Step 08 위험 제어 외부 실행 (External Action)

연결 흐름: modules/action-execution ➔ packages/policy ➔ packages/connector-runtime ➔ adapters/action-connector-fake

설명: 축적된 지식을 기반으로 외부 시스템 작업(예: 이슈 등록, 메시지 발송 등)을 수행할 때, 보안 정책 엔진이 위험도를 판정하고 사용자의 Preflight 승인을 받아 안전하게 실행 후 Audit Log를 남깁니다.

4. 종합 평가 & 준수 상태

결합도 및 격리성

각 모듈은 자신의 Domain Boundary 내에서 독립적인 계약(Contract)으로 보호되며, DB 스티마와 어댑터 구현체가 adapters/postgres-stageX 형태로 격리되어 높은 확장성과 안전성을 보장합니다.

데이터 소유권 엄수

외부 레퍼런스 및 AI의 임의 데이터 생성을 배제하고, 원본 접수부터 Canonical Knowledge까지 모든 지식 데이터에 EvidenceSpan을 명시하여 환각(Hallucination) 없는 검증 구조를 완성했습니다.
